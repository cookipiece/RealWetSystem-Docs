# 기술 사양 및 알려진 제한사항

이 페이지는 <ProductName /> v1.0.4가 아바타에 무엇을 어떻게 더하는지 숫자로 정리합니다. 일반 사용에는 읽지 않아도 됩니다.

## 지원 환경 {/* #environment */}

| 항목 | 지원 범위 |
| --- | --- |
| 에디터 | Windows의 Unity 에디터(구매 인증이 Windows 전용) |
| Unity | VRChat용 Unity 2022.3 |
| VRChat Avatars SDK | 3.10.0 이상, 4.0 미만 |
| NDMF | 1.13.1 이상, 2.0 미만 |
| Modular Avatar | 1.14.0 이상, 2.0 미만 |
| 셰이더 | lilToon 2.3.0 이상(2.3.4에서 시험), Poiyomi Toon / Pro(시험한 버전은 [호환성](./compatibility.mdx#shaders)) |
| 아바타 | Humanoid 아바타. 새 설치는 Humanoid가 아니면 막습니다. |
| 플랫폼 | Direct3D 11을 쓰는 PC 아바타. Quest·모바일은 지원하지 않습니다. |

## 동작 방식 {/* #how-it-works */}

- 젖는 위치, 퍼짐, 보호 마스크, 몸까지의 거리는 Unity에서 미리 계산해 메쉬와 텍스처에 담습니다.
- 게임 안에서는 젖음 셰이더가 그 데이터와 메뉴 값을 읽어 그립니다. 파티클, PhysBone, Collider, Contact를 더하지 않습니다.
- 미리보기와 업로드는 같은 설정과 같은 계산을 씁니다.
- NDMF 플러그인 이름은 **RealWetSystem**입니다.

## 동기화 파라미터 {/* #parameters */}

고른 메뉴 항목의 파라미터만 아바타에 들어갑니다.

| 메뉴 | 파라미터 | 동기화 | 저장 | 처음 값 |
| --- | --- | --- | --- | --- |
| 의상 젖음 표시 | `Cooki/ClothWetEnable` | 1비트 | 저장 | 켜짐 |
| 젖음 양 (RealSweatSystem 없이 쓸 때) | `Cooki/ClothWetAmount` | 8비트 | 저장 | 0% |
| RealSweat 연동 | `Cooki/ClothWetSweatLink` | 1비트 | 저장 | 켜짐 |
| 젖음 양 (연동 해제 시) | `Cooki/ClothWetManualAmount` | 8비트 | 저장 | 0% |
| 전체 영역 젖음 | `Cooki/ClothWetWhole` | 1비트 | 저장 | 꺼짐 |
| 빠른 건조 | `Cooki/ClothWetFastDry` | 1비트 | 저장 안 함 | 꺼짐 |
| 현재 상태 고정 (촬영용) | `Cooki/ClothWetHold` | 1비트 | 저장 안 함 | 꺼짐 |
| 나에게만 보이기 (RealSweatSystem 없이 쓸 때) | `Cooki/ClothWetLocalOnly` | 1비트 | 저장 | 꺼짐 |
| 중요 부위 비침 보호 | `Cooki/ClothWetProtect/All` | 1비트 | 저장 안 함 | Unity 설정값(새 설치 켜짐) |
| 비침 보호 범위 (50%=기본) | `Cooki/ClothWetProtectRange` | 8비트 | 저장 | 50% |
| 비침 보호 강도 (100%=완전히 막음) | `Cooki/ClothWetProtectStrength` | 8비트 | 저장 | 100% |
| 젖은 옷 나에게만 보이기 (RealSweatSystem과 함께 쓸 때) | `Cooki/ClothWetLocalOnly` | 1비트 | 저장 | 꺼짐 |
| 최대 젖는 범위 (%) | `Cooki/ClothWetProgressLimit` | 8비트 | 저장 | Unity 설정값 |
| 젖음 표현 (50%=기본) | `Cooki/ClothWetAppearance` | 8비트 | 저장 | 50% |
| 젖은 광택 (50%=기본) | `Cooki/ClothWetGloss` | 8비트 | 저장 | 50% |
| 비침 강도 (50%=기본) | `Cooki/ClothWetSeeThroughStrength` | 8비트 | 저장 | 50% |
| 젖음 비침 모드 | `Cooki/ClothWetSeeThroughModeV2` | 8비트 | 저장 | 설정대로 |
| 젖음 경계 | `Cooki/ClothWetEdgeSoftness` | 8비트 | 저장 | 50% |
| 젖은 옷 그림자 완화 | `Cooki/ClothWetSsaoRelief` | 1비트 | 저장 | 켜짐 |
| 의상별 편차 줄이기 | `Cooki/ClothWetOutfitCorrection` | 1비트 | 저장 | Unity 설정값(새 설치 켜짐) |
| 젖는 범위만 넓히기 (고급) | `Cooki/ClothWetRangeExpansion` | 8비트 | 저장 | 0% |
| 의상별 표시 그룹 | `Cooki/ClothWetGroup…` | 그룹마다 1비트 | — | 켜짐 |

표는 게임 안 메뉴의 순서(메인 페이지, **비침 보호**, **젖음 조절**)를 따릅니다.

- 추천 메뉴는 87비트, 의상별 표시 그룹 6개까지 모두 넣으면 94비트입니다. RealSweatSystem과 함께 쓰는 아바타는 **젖은 옷 나에게만 보이기** 토글이 들어가 1비트씩 더 씁니다(88비트, 95비트). VRChat 한도는 아바타 전체에서 256비트입니다.
- **나에게만 보이기**와 **젖은 옷 나에게만 보이기**는 같은 파라미터를 씁니다. RealSweatSystem 없이 쓰는 아바타에는 앞의 것이, 함께 쓰는 아바타에는 뒤의 것이 들어갑니다.
- RealSweatSystem과 연동할 때는 RSS의 땀 파라미터(`Cooki/SweatAmount` 등)를 읽기만 합니다. RSS의 파라미터를 바꾸지 않습니다.
- 메뉴에 넣지 않은 기능은 Unity에서 정한 값으로 동작하고, 파라미터를 더하지 않습니다.
- 메뉴 한 페이지는 8칸입니다. **젖음 조절**에 9개 이상이 들어가면 7개 뒤에 **다음** 페이지가 생깁니다. <strong>젖는 범위만 넓히기 (고급)</strong>은 늘 마지막 칸입니다.

## 애니메이터 {/* #animator */}

- 업로드할 때 FX에 `Cooki Clothing Wetness/`로 시작하는 레이어를 더합니다. 레이어 수는 고른 메뉴 항목에 따라 다릅니다.
- MA Merge Animator는 쓰지 않습니다. 아바타의 다른 FX 레이어와 원본 컨트롤러는 바꾸지 않습니다.
- Write Defaults는 **Auto**면 아바타의 FX를 읽어 맞춥니다.
- **의상별 편차 줄이기**와 **최대 젖는 범위** 다이얼을 함께 넣으면, FX에 출력 그룹마다 미리 계산한 보정 클립이 늘어납니다. 동기화 비트와 게임 안 계산은 늘지 않습니다. 최대 젖는 범위는 0·5·10·20·40·60·80·100%와 Unity 기본값에서 계산값 그대로이고, 그 사이 값은 가까운 두 단계를 섞은 근사입니다.

## 렌더큐 {/* #render-queue */}

렌더큐는 그리는 순서를 정하는 숫자입니다. 낮은 값이 먼저, 높은 값이 나중에 그려집니다. <ProductName />은 젖음 복사본의 렌더큐만 바꿉니다.

| 원래 큐 | 젖음 복사본의 큐 |
| --- | --- |
| 불투명·컷아웃, 그리고 2499 이하의 투명 | 「바디·피부 땀의 큐 + 1」부터 2499 사이 |
| 2501~2999 (투명) | 같은 구간 안에서만 뒤로 |
| 3000~3099 (투명) | 같은 구간 안에서만 뒤로 |
| 그 밖의 투명 (2500, 3100 이상) | 그대로 |

- 예를 들어 RealSweatSystem 2.0.0의 땀이 2350이면 2351~2499, 바디만 있고 2000이면 2001~2499입니다.
- 바디의 큐를 읽지 못하면 2460~2499를 쓰고 알립니다.
- 불투명과 투명의 경계를 넘겨 옮기지 않습니다. 넣을 자리가 모자라면 옮기지 않고 NDMF 결과 창에 알립니다.
- 실험 기능 PCSS4VRC(lilToon)를 쓰는 파츠는 PCSS 그림자를 지키도록 2499를 넘지 않습니다.
- 수동 순서(**수동: 앞뒤 순서 지정**)는 0~39 범위입니다.

## 메쉬와 텍스처 데이터 {/* #mesh-data */}

| 데이터 | 넣는 곳 |
| --- | --- |
| 젖음 데이터(위치, 퍼짐, 보호) | 메쉬의 TEXCOORD2·TEXCOORD3(설정 화면의 UV3·UV4) 중 비어 있는 칸. 둘 다 차 있으면 텍스처에 담습니다. |
| RealRain 비 정점 번호 | TEXCOORD6(UV6). 이미 UV6을 쓰는 메쉬는 그 렌더러의 비만 끕니다. |
| 블렌드셰이프 연동 젖음의 두 번째 상태 | UV3/UV4 |
| 보호 마스크 | 텍스처(보호 영역까지의 거리를 담아 셰이더에서 매끈하게 흐림) |

- 젖는 파츠는 메쉬 복제본을 만들어 데이터를 더합니다. 원본 메쉬·FBX와 가져오기 설정은 바꾸지 않습니다.
- <ProductName />이 저장하는 메쉬는 압축하지 않습니다. FBX에서 Mesh Compression을 켠 의상은 그 메쉬만 압축하지 않은 크기로 올라갑니다.
- PC(D3D11)는 셰이더 한 패스에 텍스처 64개까지입니다. 업로드의 최종 셰이더가 이 한도를 넘으면 그 머티리얼만 마른 원본으로 돌아갑니다.

- 실험 기능이 만드는 셰이더는 이 PC에 설치된 다른 작가의 셰이더로 만든 것입니다. 내보내거나 나누어 주지 말아 주십시오.

## 알려진 제한사항 {/* #known-limits */}

- 지원하지 않는 셰이더(Sunao, UnityChanToon, UTS, Poiyomi 8.x 이하, Poiyomi Fur·Grab Pass, lilToon Fur·Gem, 사용자가 고친 셰이더)에는 젖음을 넣지 않습니다.
- 업로드하는 동안 의상 메쉬의 정점 순서, 서브메쉬, 메쉬 구조를 바꾸는 툴(찢어짐 방지 툴, 폴리곤 줄이기 툴 등)은 호환되지 않을 수 있습니다. 맞지 않게 된 의상이나 파츠는 마른 채로 올라가고, NDMF 빌드 결과 창에 이유가 남습니다. AAO, d4rk Avatar Optimizer, TexTransTool은 지원합니다.
- VRCFury를 쓴다면 1.1436.0 이상을 써 주십시오.
- lilToon Refraction / RefractionBlur는 젖은 색·광택만 더하고, 추가 비침은 넣지 않습니다.
- 서로 다른 의상끼리는 겹옷 순서를 정하지 않습니다.
- 애니메이션으로 Renderer의 **메쉬 자체**를 바꾸는 구성은 지원하지 않습니다.
- 젖음 시작점 공 하나하나를 게임 안에서 켜고 끄는 기능은 없습니다.
- 블렌드셰이프 연동 젖음은 지금 옷 모양만 보여 주며, 옷이 움직이기 전 자리의 젖음을 기억하지 않습니다.
- `_TransparentMode` 숫자만 애니메이션으로 바꾸는 lilToon 모드 전환까지는 보장하지 않습니다.
- SDK 전처리 콜백을 부르지 않는 별도 익스포트 도구에서는 업로드 마지막의 텍스처 한도 복구가 적용되지 않을 수 있습니다.
