## 설치하기 버튼이 회색 {/* #install-gray */}

1.0.0에서는 아래 경우에 **설치하기** 버튼이 회색이 되고, 그 이유가 화면에 나오지 않습니다. 1.0.1부터는 버튼 위에 이유가 나오고, 첫 번째 경우도 Unpack 없이 설치할 수 있습니다.

| 원인 | 해결 |
| --- | --- |
| 아바타가 FBX(모델 파일)를 씬에 그대로 놓은 것입니다. Unity는 이런 아바타를 고칠 수 없는 모델로 봅니다. | 먼저 씬을 저장합니다. Hierarchy에서 아바타를 우클릭 → **Prefab > Unpack Completely**를 누른 뒤, 설치 창의 **새로고침**을 누릅니다. |
| **아바타** 칸에 Project 창의 프리팹 파일이 들어갔습니다. | Hierarchy에서 아바타를 클릭한 뒤, 설치 창의 **감지**를 누릅니다. |
| Unity가 Play 중입니다. | Play를 끝낸 뒤 다시 시도합니다. |

그래도 회색이면, Hierarchy가 보이는 Unity 전체 화면을 BOOTH 메시지로 보내 주십시오.

## 스크립트가 깨져 보이거나 CookiTools 메뉴가 없음 {/* #scripts-missing */}

패키지를 가져왔는데 Unity 메뉴줄에 **CookiTools**가 없거나, `RealWet` 오브젝트나 의상의 컴포넌트가 **Missing Script**로 보이면 아래를 차례로 확인해 주십시오. Missing Script가 된 컴포넌트는 지우지 마십시오. 원인을 고치면 다시 돌아옵니다.

### 1. 필수 패키지가 없거나 오래됨 {/* #scripts-packages */}

VCC의 **Manage Project**에서 다음 패키지를 확인하고, 지원 범위 안의 최신 버전으로 업데이트해 주십시오.

| 패키지 | 지원 범위 |
| --- | --- |
| VRChat Avatars SDK | 3.10.0 이상, 4.0 미만 |
| NDMF | 1.13.1 이상, 2.0 미만 |
| Modular Avatar | 1.14.0 이상, 2.0 미만 |
| VRCFury (쓰는 경우) | 1.1436.0 이상 |

- 새 메이저 버전(예: 2.0)이 나왔다면, 올리기 전에 [호환성](./compatibility.mdx#requirements)을 먼저 확인해 주십시오. 지원 범위 밖의 버전에서는 <ProductName />의 본체가 로드되지 않습니다.
- VRChat Avatars SDK, NDMF, Modular Avatar 중 하나라도 없거나 지원 범위 밖이면, 패키지를 가져온 뒤나 Unity를 시작한 뒤 **RealWet Dependencies** 창이 한 번 열립니다. 패키지마다 **설치 필요**, **업데이트 필요** 같은 상태와 지원 범위가 나옵니다.
- 이 창에는 버튼이 세 개 있습니다. 화면 언어를 아직 고르지 않았다면 영어로 보입니다.
  - **다시 확인**(Check Again): 패키지를 바꾼 뒤 다시 확인합니다.
  - **문의 정보 복사**(Copy Issue for Support): Unity와 패키지 버전을 복사합니다. 자동으로 보내지 않습니다.
  - **VCC 도움말**(VCC Help): VRChat의 VCC 안내 페이지를 엽니다.
- 이 상태에서 **CookiTools > RealWetSystem > Setup／Uninstall**을 누르면 설치창 대신 **RealWet — 설치 호환성 확인** 안내가 나옵니다. 아바타는 바뀌지 않습니다.
- NDMF가 아예 없으면 `RealWet` 오브젝트와 의상의 <ProductName /> 컴포넌트가 Missing Script로 보입니다.
- <ProductName />은 패키지를 자동으로 업데이트하지 않습니다.
- VRCFury는 이 창에서 확인하지 않습니다. 오래된 VRCFury는 빌드할 때 오류가 납니다. [VRCFury가 오래됨](#vrcfury-old)

### 2. 다른 패키지에 빨간 컴파일 오류가 있음 {/* #scripts-compile-error */}

어느 패키지든 빨간 컴파일 오류가 하나라도 있으면, Unity는 새로 가져온 툴을 불러오지 못합니다. 그러면 메뉴도 컴포넌트도 동작하지 않고, 위의 확인 창도 열리지 않습니다.

1. **Window > General > Console**을 엽니다.
2. 맨 위의 첫 번째 빨간 오류를 찾습니다.
3. 오류에 나온 파일 경로로 어느 패키지인지 확인하고, 그 패키지를 업데이트하거나 지웁니다.

### 3. VRChat용 Unity 2022.3 프로젝트가 아님 {/* #scripts-unity-version */}

VCC로 만든 VRChat용 Unity 2022.3 아바타 프로젝트에서 써 주십시오.

### 4. 가져온 직후임 {/* #scripts-after-import */}

가져온 직후 Console에 빨간 오류가 남아 있으면 Unity를 한 번 다시 시작해 주십시오. [이전 버전 위에 업데이트](#updating)에도 같은 안내가 있습니다.

### 5. 패키지의 일부만 가져옴 {/* #scripts-partial-import */}

가져오기 창에서 일부 파일의 체크를 끄고 가져오면 동작하지 않을 수 있습니다. `.unitypackage`를 다시 가져오고, 모든 항목에 체크한 채로 **Import**를 눌러 주십시오.

해결되면 Unity 메뉴줄에 **CookiTools**가 나옵니다. 이 PC에서 처음 쓴다면 [구매 인증](./license-activation.mdx)부터 해 주십시오.

그래도 해결되지 않으면 Console의 첫 번째 빨간 오류 전체와 VCC **Manage Project**의 패키지 목록(이름과 버전)을 함께 보내 주십시오. [문의하기](#support)

## 의상이 젖지 않음 {/* #outfit-dry */}

| 원인 | 해결 |
| --- | --- |
| 의상이 등록되지 않았습니다. | **RealWet > 의상 관리**의 목록에 그 의상이 있는지 봅니다. 없으면 **지금 의상 찾아 추가**나 **수동 추가**로 넣습니다. |
| 의상이나 파츠의 **젖음 기능 사용**이 꺼져 있습니다. | **이 의상 설정**과 **의상 파츠 설정** 위쪽의 체크를 켭니다. |
| 머리카락이나 소품처럼 몸에서 떨어진 파츠입니다. | **땀나는 곳부터**는 시작점 근처만 젖습니다. 머리카락은 보통 젖지 않는 것이 정상입니다. 젖게 하려면 인게임 **전체 영역 젖음**을 켜거나 그 근처에 [시작점](./usage/wet-start-points.mdx)을 더합니다. |
| <strong>최대 젖는 범위 (%)</strong>가 낮거나 <strong>이 머티리얼 젖음 표현 (%)</strong>이 0%입니다. | [젖음 설정](./usage/wet-settings.mdx#range)과 파츠 슬롯 카드를 확인합니다. |
| 지원하지 않는 셰이더입니다. | 파츠 카드에 <strong>RealWet이 지원하지 않는 셰이더(…)라 이 파츠는 젖지 않습니다.</strong>가 나옵니다. [호환성](./compatibility.mdx#shaders)을 확인해 주십시오. |
| 빌드에서만 젖지 않습니다. | NDMF 결과 창의 경고를 봅니다. [NDMF 경고](#ndmf-warnings)를 확인해 주십시오. |
| 업로드한 아바타 전체에서 효과가 없습니다. | [구매 인증 없이 업로드함](#not-activated)을 확인해 주십시오. |

**비치지 않음** 의상은 몸이 비치지 않는 것이 정상입니다. 색과 광택이 바뀌는지로 젖음을 확인해 주십시오. 보호 영역은 젖음을 막지 않고 비침만 막습니다.

## 일부만 젖지 않음 {/* #partly-dry */}

| 원인 | 해결 |
| --- | --- |
| 땀이 닿지 않는 자리입니다(소매 끝, 치마 끝 등). | 정상입니다. 범위를 올리거나, 그 근처에 시작점을 더하거나, **전체 영역 젖음**을 씁니다. |
| 몸에서 멀리 떨어진 헐렁한 천입니다. | 그 파츠의 **밀착도 프리셋**을 **밀착**으로 바꿉니다. |
| 그 파츠의 머티리얼만 지원하지 않는 셰이더입니다. | 그 파츠는 원래 모습으로 남습니다. 지원 셰이더로 바꾸거나 그대로 둡니다. |
| 옷장 애니메이션으로 바뀌는 머티리얼만 젖지 않습니다. | **이 의상 설정 > 문제 해결 > 추가로 준비할 교체 머티리얼**에 그 머티리얼을 넣습니다. |
| 최적화 도구가 파츠를 합치거나 복사했습니다. | NDMF 결과 창에 **RealWet: 일부 파츠만 젖음 없이 빌드되었습니다**가 나옵니다. 아래 표를 확인해 주십시오. |
| 의상의 한 부분을 의상 루트 밖으로 옮겼습니다. | 의상 루트 아래로 되돌리면 다시 젖습니다. 빌드할 때 콘솔에 옮긴 부분의 이름이 남습니다. |

## 미리보기에서는 젖는데 빌드·재생·업로드에서 안 젖음 {/* #preview-ok-build-dry */}

미리보기에서는 젖는데 Build & Test, 재생(Play), 업로드에서 젖지 않는다면, 대개 빌드할 때 다른 툴이나 환경이 결과를 바꾼 경우입니다. 다음 순서로 원인을 찾아 주십시오.

1. 빌드나 재생 뒤 NDMF 결과 창을 봅니다. 창이 닫혀 있으면 **Tools > NDM Framework > Show NDMF Console**로 엽니다. <ProductName />이 젖음 없이 둔 의상이나 파츠는 이름과 이유가 `RealWet:`으로 시작하는 경고로 남습니다. 오류 전문은 Console에 있습니다.
2. 아래 표에서 맞는 경우를 찾아, 오른쪽 항목을 확인해 주십시오.

| 어디서 안 젖는가 | 흔한 원인 | 볼 곳 |
| --- | --- | --- |
| 업로드한 아바타에서만 효과가 모두 없음. 미리보기와 재생은 정상 | 이 PC가 구매 인증되지 않았습니다. NDMF 경고는 없고 Console에 한 줄만 남습니다. | [구매 인증 없이 업로드함](#not-activated) |
| 재생에서만 일부 의상이 마름 | 아직 준비되지 않은 의상이 있거나, 재생을 시작할 때 아바타가 꺼져 있었습니다. | [재생하면 일부 의상이 젖지 않음](#play-not-ready) |
| 업로드에서만 일부 lilToon 파츠가 마름 (PCSS4VRC 사용) | PCSS4VRC가 빌드 첫 단계에서 머티리얼을 바꿨습니다. | [PCSS4VRC가 머티리얼을 바꿈](#pcss) |

## 젖는 자리나 비침 보호 위치가 아바타와 맞지 않음 {/* #placement-mismatch */}

<ProductName />은 여러 아바타에 쓸 수 있게 범용으로 만들었지만, 아바타의 몸 모양과 본 위치에 따라 자동으로 놓은 공이 맞지 않을 수 있습니다. 이때는 공의 위치와 범위를 직접 조절해 주십시오.

| 증상 | 해결 |
| --- | --- |
| 엉뚱한 곳이 젖거나, 땀이 날 곳이 젖지 않습니다. | 그 근처의 젖음 시작점 공을 Scene에서 옮기고(W), 크기를 바꿉니다(R). [편집기 열기](./usage/wet-start-points.mdx#editor), [자주 하는 조절](./usage/wet-start-points.mdx#tips) |
| 비침 보호 영역이 가슴·사타구니에서 어긋나 있거나, 너무 작거나 큽니다. | 보호 영역을 Scene에서 옮기고(W), 돌리고(E), 크기를 바꿉니다(R). [보호 영역 편집하기](./usage/see-through-protection.mdx#editing) |
| 왼쪽과 오른쪽을 함께 고치고 싶습니다. | 두 편집기 모두 **좌우 대칭**이 있습니다. 켜고 한쪽만 고칩니다. |
| 처음 배치로 되돌리고 싶습니다. | 시작점은 [되돌리기와 다시 배치하기](./usage/wet-start-points.mdx#reset), 보호 영역은 [초기화 버튼](./usage/see-through-protection.mdx#reset)을 씁니다. |

- 고친 뒤에는 미리보기를 50%와 100%로 확인해 주십시오.
- 보호 영역은 [확인하는 방법](./usage/see-through-protection.mdx#checking)처럼 앞·옆·뒤에서 확인해 주십시오.
- 젖기 시작하는 방식이 **몸에 닿는 곳부터**이면 시작점을 쓰지 않으므로, 공을 옮겨도 젖는 자리가 바뀌지 않습니다. 인게임 **전체 영역 젖음**이 켜져 있을 때도 같습니다.

## 겹옷이 사라지거나 순서가 이상함 {/* #layer-issues */}

젖어서 비치는 옷은 몸, 속옷, 겉옷을 그리는 순서(렌더큐)가 맞아야 자연스럽게 보입니다. <ProductName />은 의상마다 겹친 모양을 보고 순서를 자동으로 정하지만, 모든 겹옷을 감지하지는 못합니다. 감지하지 못한 파츠는 같은 큐가 되거나 순서가 뒤집혀, 젖었을 때 안쪽 옷이 사라진 것처럼 보일 수 있습니다.

먼저 그 의상의 **이 의상 설정 > 의상 파츠 > 겹옷 그리기 순서 · 렌더 큐**를 열어 주십시오. 사용법은 [겹옷 순서](./usage/outfit-settings.mdx#layer-order)에 있습니다. 그다음 아래에서 맞는 경우를 찾아 주십시오.

### 같은 의상 안의 속옷이 각도에 따라 사라짐 {/* #layer-same-queue */}

- **원인:** 서로 닿거나 겹친 두 파츠가 같은 큐입니다. 그러면 Unity가 먼저 그릴 쪽을 정하므로, 젖었을 때 안쪽 옷이 사라질 수 있습니다. 파츠가 서로 교차하거나, 너무 붙어 있거나, 파츠가 많아 판단할 근거가 부족하면 이렇게 남습니다.
- **알아보는 법:** 순서 목록에 **같은 큐** 표시가 나옵니다. 빌드 뒤에는 NDMF 결과 창에 **RealWet: 겹옷 그리기 순서를 확인해 주십시오**가 나옵니다. 감지하지 못한 경우에는 표시도 경고도 없을 수 있습니다.
- **해결:** 목록에서 두 파츠 중 하나를 드래그해 안쪽을 위로, 바깥쪽을 아래로 둡니다. 표시가 없어도 같은 방법으로 고칩니다.
- 머리카락 그림자처럼 같은 메쉬를 한 번 더 그리는 머티리얼은 바탕 바로 다음에 자동으로 놓습니다. 그림자가 따로 된 오브젝트라면 목록에서 바탕보다 아래로 드래그해 주십시오.

### 따로 등록한 겉옷이나 머리카락 아래에서 안쪽 옷이 사라짐 {/* #layer-other-outfit */}

- **원인:** 순서는 의상마다 따로 정합니다. 서로 다른 의상끼리는 순서를 정하지 않으므로, 따로 등록한 겉옷이 아래 옷보다 먼저 그려질 수 있습니다. 옷장으로 켜고 끄는 겉옷을 다른 의상으로 등록한 경우도 같습니다.
- **해결:** 겉옷 의상의 슬롯을 **수동: 앞뒤 순서 지정**으로 바꾸고 큰 숫자(예: 20)를 주거나, 겉옷을 아래 옷과 같은 의상으로 함께 등록합니다.
- 같은 의상 안에서는 업로드 때 꺼져 있다가 게임에서 켜는 파츠도 같은 순서를 받습니다.

### 머티리얼을 바꾼 상태나 최적화 도구를 쓴 뒤에만 이상함 {/* #layer-swapped */}

- **원인:** 애니메이션, MA Material Setter, Material Swap으로 바꾼 머티리얼은 렌더 방식(불투명·컷아웃 또는 투명)이 원래와 같으면 원래 순서를 씁니다. 렌더 방식이 다르면 그 렌더 구간의 맨 앞에 놓입니다. 최적화 도구가 파츠를 바꿔 원래 어느 파츠인지 알 수 없을 때도 맨 앞에 놓고, 순서가 다른 파츠를 합쳤을 때는 그중 가장 안쪽 순서를 씁니다.
- **알아보는 법:** 최적화 도구 때문이라면 빌드 뒤 NDMF 결과 창이나 콘솔에 파츠 이름과 함께 **머티리얼의 렌더 구간이 바뀌었습니다**, **원래 어느 파츠인지 알 수 없었습니다**, **가장 안쪽 순서를 씁니다** 같은 줄이 남습니다.
- **해결:** 교체 머티리얼은 원래 머티리얼과 같은 렌더 방식으로 맞춰 주십시오. Build & Test에서 바꾼 상태도 확인하고, 다른 파츠와 같은 큐가 되었다는 경고가 나오면 순서 목록에서 드래그합니다. 교체 머티리얼만 젖지 않는 문제는 [일부만 젖지 않음](#partly-dry)을 확인해 주십시오.

### '머티리얼 렌더큐 유지' 슬롯이 있음 {/* #layer-preserve */}

- **원인:** **머티리얼 렌더큐 유지**는 예전 설정입니다. 순서를 계산하지 않고 젖음 복사본의 기본 큐를 그대로 씁니다. 불투명·컷아웃 옷은 모두 같은 큐(2460)가 되므로, 겹친 파츠의 앞뒤를 Unity가 정합니다. 이 경우에는 빌드 경고가 나오지 않습니다.
- **알아보는 법:** 의상의 모든 슬롯이 이 설정이면 순서 목록에 **이 의상은 모든 슬롯이 '머티리얼 렌더큐 유지'(예전 설정)입니다.**가 나옵니다.
- **해결:** **자동 순서로 바꾸기**를 누르거나, 그 슬롯을 **자동: 겹옷 안팎 감지**로 바꿉니다. Ctrl+Z로 되돌릴 수 있습니다.

### 렌더 구간이 달라 순서를 맞출 수 없음 {/* #layer-bands */}

- **원인:** 불투명·컷아웃 옷과 투명 옷은 그리는 구간이 다릅니다. <ProductName />은 파츠를 다른 구간으로 옮기지 않습니다. 그래서 안쪽 옷이 투명이고 겉옷이 불투명이면 안쪽 옷이 나중에 그려질 수 있습니다. 바디나 피부 땀의 큐가 2499에 가까워 옷을 넣을 자리가 모자랄 때도 원래 큐를 그대로 씁니다.
- **알아보는 법:** NDMF 결과 창에 **…의 렌더 구간이 더 늦게 그려집니다** 또는 **…넣을 자리가 없어서, 다음 파츠는 원래 큐를 그대로 썼습니다**가 나옵니다.
- **해결:** <ProductName />은 원본 머티리얼과 바디를 바꾸지 않습니다. 두 옷의 렌더 방식을 맞출지는 직접 정해 주십시오. 그 슬롯에 **직접: 렌더큐 지정**을 쓸 수도 있지만, 구간을 넘는 숫자는 깊이와 그림자가 달라질 수 있으므로 미리보기로 확인해 주십시오.

### 등록하지 않은 파츠와 겹침 {/* #layer-unmanaged */}

- **원인:** <ProductName />에 등록하지 않은 파츠(스타킹, 레이스 등)의 순서는 바꾸지 않습니다. 그 파츠의 큐가 2460보다 낮으면 젖은 옷을 그 뒤에 그립니다. 순서 목록 위에 **RealWet이 바꾸지 않는 … 다음**으로 보입니다. 2460 이상이면 순서를 맞추지 않으므로, 젖은 옷 아래에서 사라지거나 위로 보일 수 있습니다.
- **해결:** 그 파츠를 같은 의상에 함께 등록하면 함께 순서를 정합니다. 젖은 모습이 필요 없다면 그 슬롯의 <strong>이 머티리얼 젖음 표현 (%)</strong>을 0%로 둡니다.

### 렌더큐를 바꾼 뒤 다른 옷이 이상해짐 {/* #layer-side-effects */}

:::caution[렌더큐를 바꾸면 다른 옷의 모습도 바뀔 수 있습니다]
렌더큐는 아바타 전체에서 그리는 순서입니다. 의상 하나의 숫자를 바꾸면, 그 앞뒤에 그려지는 장식, 투명 효과, 다른 의상과의 겹침도 바뀔 수 있습니다.

- <ProductName />은 원본 머티리얼의 렌더큐를 바꾸지 않습니다. 바뀌는 것은 미리보기와 업로드에 쓰는 젖음 복사본의 큐뿐입니다. 하지만 게임에서는 그 복사본이 그려지므로, 보이는 순서는 바뀝니다.
- 옷 제작자가 렌더큐 숫자로 모양을 맞춘 의상(스텐실, 레이스, 투명 효과 등)은 순서가 바뀌면 모양도 바뀔 수 있습니다. 자동 순서도 젖음 복사본의 숫자를 다시 정합니다.
- 수동·직접 숫자를 정하면 같은 의상의 자동 파츠가 그 숫자를 피해 가므로, 다른 파츠의 숫자도 움직일 수 있습니다.
- 수동 숫자는 같은 바디를 쓰는 의상끼리 같은 기준으로 셉니다. 큰 숫자를 주면 다른 의상의 파츠보다 나중에 그려집니다.
- 드래그와 **직접: 렌더큐 지정**은 고정 숫자입니다. 나중에 바디나 RealSweat이 바뀌어도 따라 움직이지 않습니다.

바꾼 뒤에는 미리보기에서 앞·옆·뒤를 확인해 주십시오. 바꾸고 싶지 않았던 슬롯은 **자동: 겹옷 안팎 감지**로 되돌립니다. 의상 전체는 **겹옷 순서를 자동으로 되돌리기**로 한 번에 되돌릴 수 있습니다. 옷 제작자가 정한 숫자의 순서를 지켜야 하는 의상은 같은 화면의 **안쪽 → 바깥쪽 판정 우선**을 끕니다. 그러면 원래 머티리얼 큐의 순서를 먼저 따르고, 같은 큐끼리만 안팎으로 나눕니다. 투명 효과 머티리얼처럼 제작자의 숫자를 그대로 써야 하는 슬롯 하나에만 **머티리얼 렌더큐 유지**를 쓸 수도 있습니다. 불투명·컷아웃 옷에는 쓰지 마십시오.
:::

## 구매 인증 없이 업로드함 {/* #not-activated */}

인증하지 않은 PC에서 업로드하면 <ProductName />의 효과가 업로드에서 조용히 빠집니다. 빌드는 실패하지 않고 창도 뜨지 않습니다.

- Unity의 미리보기와 재생(Play)에서는 젖은 모습이 그대로 보입니다. 업로드한 아바타에서만 빠집니다.
- Console에 `RealWetSystem: 이 PC는 구매 인증이 되어 있지 않아, 업로드할 때 … 효과가 빠집니다.`로 시작하는 경고가 한 줄 남습니다.
- 설치창의 아바타 칸 바로 아래에 안내와 **인증 창 열기** 버튼이 나옵니다.
- RealRain의 비에 옷이 젖는 모습도 <ProductName />이 그리므로 함께 빠집니다.

**해결:** **CookiTools > RealWetSystem > Purchase Activation**에서 인증한 뒤 다시 업로드해 주십시오. [구매 인증](./license-activation.mdx)

## PCSS4VRC가 머티리얼을 바꿈 {/* #pcss */}

PCSS4VRC를 쓰는 아바타에서는 PCSS4VRC가 빌드 첫 단계에서 lilToon 머티리얼을 `_pcss` 머티리얼로 바꿉니다. 그래서 미리보기에서 젖은 파츠가 업로드에서는 젖지 않을 수 있습니다.

- 이런 파츠는 의상·파츠 미리보기 위에 **업로드 때 이 부분은 젖지 않습니다** 안내와 바로 켜는 버튼이 나오고, 빌드할 때 NDMF 경고 하나로 알립니다.
- **해결:** 설치창 **고급 설정 > 실험 기능**에서 **PCSS4VRC(lilToon)** 지원을 켜고 **업데이트하기**를 누릅니다. 그러면 PCSS 의상도 젖습니다. 실험 기능이므로 [고급 기능](./advanced.mdx#experimental)을 먼저 읽어 주십시오.
- PCSS4VRC가 셰이더를 바꾸지 않는 lilToon 사용자 셰이더를 쓰는 파츠는 업로드에서도 젖습니다.
- 실험 기능을 켜도 lilToon **Multi**·**MultiOutline**(그리고 Tessellation·Lite) 계열을 PCSS4VRC가 바꾼 파츠는 젖지 않고, NDMF 경고가 나옵니다. 1.0.0의 경고는 기능을 켜라고 안내할 수 있지만, 이미 켜져 있다면 이 계열 때문입니다. 그 머티리얼을 lilToon 표준 셰이더로 바꾸거나 PCSS4VRC의 변환 대상에서 빼 주십시오.

## VRCFury가 오래됨 {/* #vrcfury-old */}

VRCFury를 함께 쓰는 아바타에서 빌드할 때 `SweatAmount`라는 말이 들어간 오류가 나면, VRCFury가 오래된 판일 수 있습니다. 1.1258 이하의 VRCFury에서 이 오류가 확인되었습니다.

**해결:** VCC에서 VRCFury를 **1.1436.0 이상**으로 업데이트한 뒤 다시 빌드해 주십시오. VRCFury를 쓰지 않는 아바타에는 해당하지 않습니다.

## 의상 메쉬를 바꾸는 툴 {/* #mesh-tools */}

업로드하는 동안 의상 메쉬의 정점 순서, 서브메쉬, 메쉬 구조를 바꾸는 툴은 <ProductName />과 호환되지 않을 수 있습니다. 찢어짐 방지(안티 리핑) 툴이나 폴리곤 줄이기 툴이 그런 예입니다.

- <ProductName />은 젖음 데이터를 의상 메쉬에 맞춰 넣습니다. 다른 툴이 메쉬를 바꿔 맞지 않게 된 의상이나 파츠는 젖음 없이 마른 채로 올라갑니다.
- 빌드는 멈추지 않습니다. NDMF 빌드 결과 창에 그 의상(또는 파츠) 이름과 이유가 경고로 남습니다.
- AAO(Avatar Optimizer), d4rk Avatar Optimizer, TexTransTool은 지원합니다. [호환성](./compatibility.mdx#optimizers)을 확인해 주십시오.
- 그 의상을 젖게 하려면 그 툴의 대상에서 젖는 의상을 빼고 다시 빌드해 주십시오.

## 한 씬에 아바타가 여러 개 {/* #multiple-avatars */}

<ProductName />은 아바타마다 따로 동작합니다. 같은 씬에 아바타가 여러 개 있어도 서로의 설정을 쓰지 않습니다.

- 아바타마다 따로 설치해야 합니다. 설치창의 **아바타** 칸에 지금 고른 아바타가 맞는지 확인해 주십시오.
- 한 아바타에 `RealWet` 오브젝트가 두 개 이상이면 **중복 오류**가 나옵니다. 하나만 남겨 주십시오.
- 다른 아바타에서 복사해 온 의상이 그 아바타의 바디나 본을 가리키면, 미리보기가 무엇이 어느 아바타를 가리키는지와 고치는 방법을 알려 줍니다.
- 두 번째 아바타에서 처음 확인한 것이 머리카락처럼 원래 잘 젖지 않는 파츠는 아닌지 확인해 주십시오. 셔츠처럼 몸에 닿는 옷으로 먼저 확인하면 차이를 알기 쉽습니다.
- NDMF·Modular Avatar는 정식판에서 확인했습니다. 시험판(베타)을 쓰고 있다면 정식판으로 바꿔 다시 확인해 주십시오.

## 첫 빌드가 오래 걸림 {/* #long-first-build */}

처음 빌드하거나 처음 미리보기할 때는 젖음 셰이더를 만들고 Unity가 컴파일합니다. 머티리얼이 많은 아바타는 **수십 분**이 걸릴 수 있습니다. 이때 Unity 창이 거의 움직이지 않아 멈춘 것처럼 보일 수 있습니다.

{/* SHOT U28: build progress bar */}

1. **기다려 주십시오.** 업로드 중에는 `RealWet: 의상 형상 계산 중 (3/22) · 의상 이름`처럼 단계와 순서, 의상 이름이 진행 표시로 나옵니다. Unity 자체의 셰이더 컴파일 중에는 진행 표시가 오래 그대로일 수 있고, 창 없이 진행되기도 합니다.
2. **작업 관리자에서 CPU를 확인합니다.** Unity나 `UnityShaderCompiler`가 CPU를 쓰고 있다면 아직 일하는 중입니다. 끄지 말고 기다려 주십시오.
3. CPU가 몇 분 동안 거의 0%이고 진행 표시도 바뀌지 않을 때만 멈춘 것으로 봅니다. 그때는 Console의 첫 빨간 오류와 기다린 시간을 기록해 문의해 주십시오.

- 두 번째 빌드부터는 첫 빌드에서 만든 셰이더 캐시를 다시 쓰므로 훨씬 짧습니다.
- 방송이나 녹화처럼 PC가 바쁠 때는 더 오래 걸립니다. 첫 빌드는 PC가 한가할 때 미리 해 두는 편이 좋습니다.
- **RealWet > 의상 관리 > 필요한 의상만 준비**로 빌드 전에 미리 준비해 둘 수 있습니다.
- 설치창의 **설치하기**·**업데이트하기**와 재생(Play)에 처음 들어갈 때도 진행 표시줄이 나옵니다. 지금 하는 일이 보이는 동안은 기다려 주십시오.

자세한 시간은 [성능](./performance.mdx#build-time)을 확인해 주십시오.

## 첫 업로드가 오래 걸림 {/* #first-upload */}

첫 업로드는 첫 빌드와 같은 셰이더 준비에 더해, VRChat SDK의 셰이더 컴파일과 업로드 파일 압축이 있어 오래 걸립니다.

- 젖는 머티리얼마다 젖음 셰이더가 들어가므로, 업로드 파일이 커지고 압축에도 시간이 걸립니다. [성능](./performance.mdx#upload-size)을 확인해 주십시오.
- 업로드할 때 Poiyomi가 머티리얼을 잠그는 시간도 더해집니다.
- 같은 설정으로 두 번째 업로드부터는 짧아집니다.

## Hold on 창 {/* #hold-on */}

Unity의 **Hold on** 창은 Unity가 작업을 끝낼 때까지 기다리라는 뜻입니다.

| 언제 | 원인과 해결 |
| --- | --- |
| 처음 미리보기, 처음 빌드, 셰이더 업데이트 직후 | 젖음 셰이더를 준비하는 중입니다. 기다려 주십시오. |
| 패키지를 가져온 직후 | Unity가 스크립트와 셰이더를 가져오는 중입니다. 기다려 주십시오. |
| Unity를 앞에 두고 아무것도 하지 않을 때 | <ProductName />은 Unity가 뒤로 가 있을 때만 미리 준비합니다. 그래도 나온다면 다른 툴이나 Unity 자체의 작업일 수 있습니다. |
| 다른 앱을 쓰다가 Unity로 돌아올 때 | 미리 준비하던 작업이 멈추는 짧은 시간입니다. 중간에 끊을 수 없는 셰이더 준비는 Unity가 3분 넘게 뒤로 가 있을 때만 시작합니다. |

**Hold on**이 같은 동작에서 자꾸 길게 나온다면, 그 동작과 Console 내용을 기록해 문의해 주십시오.

## 메뉴·파라미터가 한도를 넘음 {/* #over-limit */}

VRChat은 아바타 하나의 동기화 파라미터를 **256비트**까지 쓸 수 있습니다. <ProductName />의 추천 메뉴는 87비트입니다. RealSweatSystem이나 다른 도구와 합쳐 한도를 넘으면 VRChat SDK가 업로드를 막습니다.

1. **RealWet > 인게임 메뉴**의 **최종 동기화 비용**에서 <ProductName />이 쓰는 양을 확인합니다.
2. 쓰지 않는 다이얼의 체크를 끕니다. 다이얼은 하나에 8비트, 토글은 1비트입니다. 예를 들어 **젖는 범위만 넓히기**, **젖음 경계**, **젖음 표현**을 빼면 24비트가 줄어듭니다.
3. **인게임 메뉴 적용 / 갱신**을 누르고 다시 빌드합니다.

- 버튼을 뺀 기능은 Unity에서 정한 값으로 계속 동작합니다.
- 메뉴 한 페이지는 8칸입니다. <ProductName />은 칸이 모자라면 **다음** 페이지를 만들고, 메인 메뉴는 늘리지 않습니다.
- VRCFury Parameter Compressor 같은 파라미터 압축 툴을 쓸 수도 있습니다. 압축 툴이 젖음 파라미터를 바꾸면 NDMF 결과 창에 알립니다.

## 메뉴가 안 보임 {/* #menu-missing */}

1. 메인 메뉴에서 **젖음**(일본어 **濡れ**, 영어 **Wet**)을 찾습니다.
2. 메뉴 위치를 바꿨다면 `RealWet` 오브젝트의 **MA Menu Installer**에 지정한 메뉴 안을 확인합니다.
3. **RealWet > 인게임 메뉴**에서 **인게임 메뉴 적용 / 갱신**을 누릅니다.
4. 다시 빌드하고 그 아바타를 확인합니다. 빌드가 실패했다면 이전 아바타를 보고 있을 수 있습니다.

- 메뉴 파일이 없어졌다면 저장된 씬을 열 때 <ProductName />이 다시 만들고 연결합니다. 콘솔에 <strong>RealWet 인게임 메뉴 파일이 없어서 RealWet이 다시 만들고 연결했습니다. 씬을 저장해 주십시오.</strong>가 남으니 씬을 저장해 주십시오.
- 메뉴를 직접 옮기거나 다른 메뉴로 바꿨다면 <ProductName />은 그 메뉴를 그대로 둡니다. 다시 만들려면 `RealWet` 오브젝트의 **MA Menu Installer**를 지운 뒤 **인게임 메뉴** 탭의 **인게임 메뉴 고치기**를 눌러 주십시오.
- 메뉴가 다른 언어로 보이면, Unity에서 원하는 언어를 고른 뒤 메뉴를 갱신하고 다시 빌드해 주십시오.
- 메뉴 버튼은 있는데 아이콘만 없다면, 패키지의 `Icons` 폴더를 다시 가져온 뒤 메뉴를 갱신해 주십시오. 기능은 그대로 쓸 수 있습니다.

## 재생하면 일부 의상이 젖지 않음 {/* #play-not-ready */}

재생 버튼을 누를 때 아직 준비되지 않은 의상이 있으면, <ProductName />이 재생을 잠시 기다리게 하고 그 의상을 준비합니다. 준비가 끝나면 재생이 자동으로 시작됩니다.

{/* SHOT U29: Game view overlay before Play */}

- 기다리는 중에 재생 버튼을 한 번 더 누르면 바로 시작합니다. 이때 준비되지 않은 의상은 그 재생에서만 젖지 않습니다.
- 재생을 끝내면 그 의상부터 준비하고, 다음 재생부터 젖습니다.
- 재생을 시작할 때 꺼져 있다가 재생 중에 켠 아바타는 그 재생에서 젖지 않습니다. 아바타를 켠 채로 다시 재생해 주십시오.

## 텍스처 한도 {/* #texture-limit */}

PC용 Unity와 VRChat은 셰이더 한 패스가 쓰는 텍스처를 64개까지만 그릴 수 있습니다. 기능을 많이 켠 Poiyomi 머티리얼은 미리보기에서 잠그기 전 셰이더를 쓰므로, 젖음을 더하면 이 한도를 넘을 수 있습니다.

- 그런 슬롯은 분홍색 대신 원래 모습으로 미리보기하고 안내를 띄웁니다.
- VRChat PC 업로드는 셰이더를 먼저 잠그므로, 이 슬롯은 대개 젖은 채로 올라갑니다.
- 업로드의 최종 셰이더도 한도를 넘으면 그 머티리얼만 원래 마른 머티리얼로 돌아갑니다. 업로드는 멈추지 않습니다.
- 젖음을 유지하려면 그 머티리얼에서 쓰지 않는 텍스처 기능(MatCap, 발광, 데칼 등)을 줄인 뒤 다시 빌드해 주십시오.

## 등록된 의상이 0개 {/* #no-outfits */}

1. 설치한 아바타 아래의 `RealWet`을 선택했는지 확인합니다.
2. **의상 관리 > 의상 자동 추가 > 지금 의상 찾아 추가**를 누릅니다.
3. 빠진 옷은 **수동 추가**에 Hierarchy의 의상 루트를 넣고 **추가**를 누릅니다.

- `EditorOnly` 의상은 기본으로 찾지 않습니다.
- 의상 루트가 바디·얼굴 메쉬 오브젝트 안에 있으면 등록되지 않을 수 있습니다. [의상 설정](./usage/outfit-settings.mdx)을 확인해 주십시오.
- <strong>×</strong>로 지운 의상은 자동으로 다시 넣지 않습니다. 수동 추가로 넣어 주십시오.

## 미리보기 문제

| 증상 | 해결 |
| --- | --- |
| 아예 시작하지 않음 | **Tools > NDM Framework > Enable Previews**가 켜져 있는지, Edit Mode인지 확인합니다. |
| 오래 걸림 | Inspector의 현재 단계를 확인합니다. 처음에는 셰이더 준비 때문에 오래 걸립니다. 버튼을 다시 누를 필요는 없습니다. |
| **일시정지 · Unity로 돌아와 주십시오** | 다른 앱으로 전환했을 뿐입니다. Unity로 돌아오면 이어집니다. |
| 중간에 꺼짐 | 관련 없는 오브젝트를 선택하거나 재생·빌드·스크립트 다시 불러오기가 일어나면 끝납니다. 다시 시작하면 됩니다. |
| 준비가 계속 필요하다고 나옴 | 시작 방식, 영역, 의상 모양, 셰이더를 바꾸면 다시 준비합니다. 아무것도 바꾸지 않았는데 반복되면 의상 이름과 이유를 기록해 문의합니다. |

## 이전 버전 위에 업데이트 {/* #updating */}

1. 업데이트하기 전에 프로젝트를 백업해 주십시오.
2. `Assets/CookiTools/RealWetSystem` 폴더를 지우지 말고, 새 패키지를 그 위에 그대로 가져와 주십시오. 먼저 제거할 필요는 없습니다.
3. 가져온 직후 Console에 빨간 오류가 남아 있으면 Unity를 한 번 다시 시작해 주십시오.
4. 설치창에서 아바타마다 **업데이트하기**를 누릅니다.
5. 처음 미리보기하거나 빌드할 때 젖음 셰이더를 다시 준비하므로 한 번 오래 걸립니다.

- 저장된 설정, 시작점, 보호 영역은 그대로 남습니다.
- 손대지 않은 예전 기본 외형만 한 번 새 기본 외형으로 바뀝니다. 이때 **RealWet > 의상 관리**에 알림과 <strong>되돌리기…</strong>가 나옵니다.
- 저장된 시작점 배치가 새 추천 배치와 다르면, 업데이트할 때 **젖음 시작점 재설정** / **기존 설정 유지**를 묻습니다. 잘 모르겠다면 **기존 설정 유지**를 고르십시오.
- 새 추천 보호 모양을 쓰려면 [업데이트한 뒤의 보호 영역](./usage/see-through-protection.mdx#after-update)을 확인해 주십시오.

자세한 순서는 [업데이트 내역](./update-changelog.mdx#how-to-update)에 있습니다.

## 제거하기 {/* #uninstall */}

- **의상 하나만 빼기:** **RealWet > 의상 관리**의 그 의상 줄에서 <strong>×</strong>를 누르거나, **젖음 기능 사용**을 끕니다. 옷 자체는 남습니다.
- **아바타에서 모두 빼기:** **CookiTools > RealWetSystem > Setup／Uninstall**의 **제거** 탭에서 **설치 제거**를 누릅니다. 확인창에서 **제거**를 누르면 `RealWet` 오브젝트와 그 아래 내용, 의상의 <ProductName /> 컴포넌트, 이 설치의 메뉴 파일을 정리합니다. 의상·바디·원본 머티리얼은 남습니다. 확인창에도 적혀 있듯이 제거는 Ctrl+Z로 되돌릴 수 없습니다.
- `RealWet` 오브젝트 아래에는 다른 의상이나 도구를 넣지 마십시오. 제거할 때 함께 지워집니다.
- 최초 설치, 전체 제거, 인게임 메뉴 생성·갱신·삭제는 Ctrl+Z로 되돌릴 수 없습니다.
- 프로젝트에서 패키지까지 지우려면, 모든 아바타에서 먼저 **설치 제거**를 한 뒤 `Assets/CookiTools/RealWetSystem` 폴더를 지워 주십시오.
