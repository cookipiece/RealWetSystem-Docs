# Changelog

This page lists the main changes in each version of <ProductName />, newest first. Before you switch to a new version, please read how to update below.

## How to update {/* #how-to-update */}

1. Please back up your avatar and project before you update.
2. Don't delete the `Assets/CookiTools/RealWetSystem` folder. Please import the new package right over it. You don't need to uninstall first.
3. When you import, <ProductName /> moves files that only existed in older versions to the system trash and reports it on one line in the Console. It doesn't touch files you added yourself or files the new package uses.
4. If red errors remain in the Console right after importing, please restart Unity once.
5. In **CookiTools > RealWetSystem > Setup／Uninstall**, press **Update** for each avatar. If the saved start point layout differs from the new recommended layout, the **Update RealWetSystem** window asks you to choose **Reset Wet Start Points**, **Keep Current Settings** or **Cancel**. If you're not sure, please choose **Keep Current Settings**. A progress bar appears while it updates.

{/* SHOT U13: update dialog Reset Wet Start Points / Keep Current Settings */}
[![Update dialog asking to reset the wet start points](/img/guide/U13-en.png)](/img/guide/U13-en.png)

6. The first preview or build after an update takes longer once, because the wet shaders are prepared again.
7. If a version changes the in-game menu's names or items, press **Update** or **Apply / Update Runtime Menu**, then please build again. An avatar you already uploaded gets the new version only after you upload it again.

- Your saved settings, start points and protection regions stay as they are. To use the new recommended protection shape, see [Protection regions after an update](./usage/see-through-protection.mdx#after-update).
- Only old default looks you never touched switch once to the new default look. When that happens, a notice and **Revert...** appear in **RealWet > Outfit Management**. If you update with **Switch it to the new default while updating** turned off in the setup window, nothing is switched.
- The menu files made for each avatar are in `Assets/CookiTools/Generated/RealWet`, outside the package folder, so overwriting the package doesn't delete them.
- Updating doesn't need purchase activation. However, uploads from a PC that is not activated leave the effects out, so please complete [purchase activation](./license-activation.mdx) on the PC you upload from.

## 1.0.3 — Outfits that stayed dry, breast bone fields, Wet Clothes Only Visible to Me {/* #103 */}

If you use 1.0.2 or earlier, import the new package over it. Your saved settings and the positions of your wet start points and protection regions do not change. On an avatar that is already installed, the in-game menu, its parameters and its sync bits also stay the same until you press **Update**.

:::note[The first upload after updating takes long once]
The first upload after updating compiles the wet shaders again once. On an avatar with many outfits it can take about 20 minutes. Even if the progress display doesn't move, please don't close Unity while it is using the CPU. The first preview can also take a little longer than usual; from the second time on it is back to normal.
:::

### Breast bone fields in the setup window

- **1. Body meshes** in the setup window now always shows the **Left breast anchor** and **Right breast anchor** fields under the body mesh. The fields hold the bones found automatically; if they are wrong, drag the avatar's breast bones into them. **Auto Find Breast Bones** clears the bones you chose and finds them again. The breast bone **Change** line that was under card 3 is gone. [Body meshes](./tutorial.mdx#body)
- If you choose a bone that the body mesh has no skin weights on (an outfit's bone, for example), a notice appears under the fields.
- When you change the breast bones on an avatar that is already installed, the **Move the chest start points and chest protection to the new bones** checkbox appears (off by default). If you check it and press **Update**, only the positions of the wet start points around the chest and of the recommended chest protection regions move to the new bones. Sizes, other start points and regions you made yourself stay as they are. If you leave it unchecked, only the bone choice is saved and the saved positions don't move.

### Avatars shrunk or re-proportioned with bone scale

- Fixed the chest start points and the recommended chest protection regions landing in a different place on avatars shrunk with bone scale (Hips, Armature and so on) than before shrinking. The same body now gets the same placement when it is shrunk.
- On avatars shrunk with bone scale, the size and the search range of the wet start points now fit the shrunken body.
- Fixed the chest protection regions landing inside the body on avatars whose torso alone was shortened with bone scale, and the armpit start points landing on top of the shoulders on avatars whose upper arms were shrunk with bone scale.
- Even if you put a tip bone into a breast bone field, the recommended chest protection region looks for the front of the chest along that breast's whole bone chain.
- These fixes apply only to start points and protection regions made from now on (a new install, a reset, or the checkbox above). Saved positions don't change. The placement on avatars that are not shrunk with bone scale doesn't change either.

### Outfits that stayed dry or looked broken

- Fixed Poiyomi Toon and Pro parts that use material-swap animations with **Apply Wet to Animated Material Swaps** turned off not getting wet properly. With Poiyomi 10.0.20 and later and Poiyomi 11, parts with overlapping UV0 (mirrored left and right, for example) were uploaded dry. With earlier Poiyomi versions, parts whose materials don't use an outline failed a check at upload and got a warning.
- Fixed a slot becoming invisible or pink on Poiyomi 10.0.20 and later and Poiyomi 11 parts that use both UV3 and UV4 when the wet material went over the texture limit (64). Now only that slot goes back to its original material, as on other parts. [Texture limit](./troubleshooting.mdx#texture-limit)
- When the project sets `LILTOON_DISABLE_ASSET_MODIFICATION` and every lilToon outfit is built dry, RealWet now says that this setting is the cause, where it is set and how to fix it. Up to 1.0.2 the notice said the lilToon version **has not been verified yet**. The notice has a **Remove it from the settings and make lilToon clothing wet** button. [lilToon's shader importer is turned off](./troubleshooting.mdx#liltoon-importer-off)
- Fixed every lilToon outfit being built dry in projects where another asset owns the GUID of lilToon's importer script. In such a project, selecting one of <ProductName />'s lilToon shader files (`.lilcontainer`) shows `(Failed To Load Script Object)` at the top of the Inspector. <ProductName /> doesn't change any file in your project. [lilToon outfits stay dry and (Failed To Load Script Object) appears](./troubleshooting.mdx#liltoon-script-object)
- The report from **Copy Diagnostic Report** now says where lilToon's importer was found and whether <ProductName />'s lilToon shader files are imported as shaders.

### Wet look

- Fixed white and bright clothes looking almost the same when you raised the in-game **Wet Gloss (Default 50%)** above 50%. On outfits with **Even Wet Look for Every Outfit (New Look)** on (the default), bright clothes with the **Cotton · Knit · Denim (Recommended)** or **In Between** fabric now get much more of the broad watery gloss above 50%, and at 100% the wet gloss is clearly visible even on white clothes. As before, the gloss never gets brighter than the white of that scene.
- At 50% or below, on mid-tone and dark clothes, with other fabrics and on outfits with the new look off, nothing changes. Saved settings don't change. On an avatar that used Wet Gloss above 50%, bright clothes shine more than before once you upload again after updating.

### In-game menu

- Added **Wet Clothes Only Visible to Me** (Korean **젖은 옷 나에게만 보이기**, Japanese **濡れた衣装を自分にだけ表示**) to the **Wet** menu of avatars that also use RealSweatSystem. While it is on, other players see your outfits dry (no wet color, gloss or see-through), and you still see them wet, also in mirrors and photos. It is one saved, synced toggle (+1 bit) and it starts off. [Wet Clothes Only Visible to Me](./usage/in-game-menu.mdx#linked-local-only)
- It goes at the bottom of the **See-Through Protection** page. On an avatar without that page it goes on the main page after **Hold Current State (For Photos)**. No other menu item moves. If neither place has a free slot, that upload leaves it out and the NDMF build results say so. The build continues.
- An avatar that is already installed gets it when you press **Update** in the setup window (it starts off). Until then its menu, parameters and sync bits stay the same. Other saved settings and in-game values don't change either.
- **Only Visible to Me** on avatars without RealSweatSystem works as before. The two toggles use the same parameter (`Cooki/ClothWetLocalOnly`).
- The wet look from RealRain's rain is hidden from other players too.
- On an avatar that gets this toggle (one that also uses RealSweatSystem), the recommended menu is 88 bits, and 95 bits with every item. Without RealSweatSystem it stays 87 bits and 94 bits. [Sync cost](./usage/in-game-menu.mdx#sync-cost)

### Notices and wording

- If you use VRCFury, please use 1.1436.0 or later. If you run short of synced parameter space (256 bits), we recommend using the Parameter Compressor of VRCFury 1.1436.0 or later together with it. [Compatibility](./compatibility.mdx#requirements)
- Added 11.0.44 to the tested Poiyomi versions. [Compatibility](./compatibility.mdx#shaders)

## 1.0.2 — Outfits that stayed dry, and steps that looked frozen during setup {/* #102 */}

If you use 1.0.1 or 1.0.0, import the new package over it. Your saved settings do not change. The in-game menu's parameters and sync bits stay the same too; only a few English, Japanese and Korean menu names change from your next upload.

### Outfits that stayed dry

- Fixed every uploaded outfit staying dry on avatars that use VRCFury 1.1258 or earlier. Please keep using VRCFury 1.1436.0 or later. [VRCFury is too old](./troubleshooting.mdx#vrcfury-old)
- When an avatar linked with RealSweatSystem is uploaded and the RSS sweat input can't be used (RealSweatSystem is not activated on this PC, the sweat parameter's sync is off, and so on), the clothes no longer all stay dry. RealWet now builds as if **Link RealSweat** were off, using the in-game **Wetness Amount (Unlinked)** dial, and the NDMF build results say why and what to do.
- Fixed a part slot's wet look and see-through settings resetting when you swapped its material for another one of the same family after installing (another color of the same outfit, for example). The settings now carry over.
- Fixed overlapping parts in one outfit, such as a shirt over a bikini, not showing through at all with **Outerwear Only (Not Underwear) (Recommended)**. Now the outer part shows through, and the inner part under it doesn't. This applies only to outfits you register from now on.
- Fixed some outfits that use the experimental lilSSRT or PCSS4VRC (lilToon) support staying dry in the build, and the draw order of semi-transparent lilSSRT outfits changing. Existing lilSSRT outfits are prepared again once after the update. [Advanced features](./advanced.mdx#experimental)
- Fixed a whole outfit staying dry when its FBX has Read/Write turned off and VRCFury makes a copy of its materials during the build. It also gets wet with Avatar Compressor (LAC). RealWet doesn't change your FBX settings. [Another tool changed the material during the build](./troubleshooting.mdx#material-replaced)

### Steps that looked frozen while installing or adding outfits

- **Add Recommended** and **Add Selected Outfits** in the outfit chooser show each outfit's name on the progress bar. The body is read only once, however many outfits you add. The result is the same.
- The progress bar keeps moving during the chest and groin protection step of **Install**.
- If the scene has unsaved changes when you press **Install**, you are asked once: **Save and install** or **Install without saving**.
- Shader preparation done while Unity is in the background now shows a **RealWet shader preparation (n/m)** progress bar. After each shader it checks whether you came back; if you did, it stops there and continues next time. It waits while less than 4 GB of memory is free.
- The preview prepares wet shaders two at a time, as Play does. Shader compiling uses less memory, and the result is the same.
- Removed needless work that the setup window and the preview did on every redraw.

### Notices and wording

- For avatars that use PCSS4VRC, the notice above the preview, the part slot, the **Experimental** card of the setup window and the NDMF build results now say that lilToon Multi, Tessellation and Lite parts stay dry in the upload even with the experimental feature on. [PCSS4VRC replaced the materials](./troubleshooting.mdx#pcss)
- The first-install question about turning on lilSSRT or PCSS4VRC appears only when this avatar actually uses those shaders.
- Poiyomi 8.x and earlier and PCSS4Poi parts now also say what makes them wet (Poiyomi 9 or later).
- When a newer lilSSRT was imported over an older one and its shaders stayed in an old folder (for example `Shaders/SSRTAO`), RealWet names the folder it found and the steps to fix it. [lilSSRT shaders left in an old folder](./troubleshooting.mdx#lilssrt-old-folder)
- The notice for the RealWet internal module installed in Poiyomi now also fits recent Poiyomi versions without the **Poi > Installed Modules** menu. Poiyomi with another author's shader module now also gets the steps to remove that module. [You installed the RealWet internal module in Poiyomi](./troubleshooting.mdx#poi-internal-module)
- When a material copy that another tool made during the build leaves a part dry, the NDMF build results also say which check didn't match. [Another tool changed the material during the build](./troubleshooting.mdx#material-replaced)
- The report from **Copy Diagnostic Report** lists each installed experimental shader (lilSSRT, PCSS4VRC (lilToon)): whether it is on, whether it can be used, where it was found and the checked version.
- The yellow warning line that appeared in the Console on every upload is now a normal log line.
- In-game menu names: in the English menu, the ends of **Wet Appearance**, **See-Through Strength** and **Wet Gloss** are shortened to `(Default 50%)` so they aren't cut off. The English word "Sweat" left in the Japanese and Korean windows and menus now uses each language's word (汗, 땀), and Japanese parentheses are full-width.
- The missing parts of the Japanese recovery notice were filled in. The short reasons in the outfit chooser and the default wet start point names now appear in the window language you chose. Saved values and the Hierarchy marker names don't change.

## 1.0.1 — Install button reasons {/* #101 */}

If you use 1.0.0, import the new package over it. Your saved settings, in-game menu and upload results do not change.

- When **Install** or **Update** in the setup window can't be clicked, the reason is shown right above the button. Play mode, a prefab file from the Project window and a scene that isn't open each have their own message.
- If you put a prefab file from the Project window into the **Avatar** field and the scene has exactly one copy of that avatar, the window switches to the copy in the scene and says so in one line. If the scene has none or several, it asks you to pick the avatar in the Hierarchy.
- Avatars made by placing a model file such as an FBX straight into the scene and adding a VRC Avatar Descriptor can now be installed without Unpack. Outfits inside that model file can be made wet too. [Install button is gray](./troubleshooting.mdx#install-gray)

## 1.0.0 — First public release {/* #100 */}

The first public release of <ProductName />.

### What's included

- **Setup window:** In **CookiTools > RealWetSystem > Setup／Uninstall**, choose the body meshes, the maximum wet range, where wetness starts and how new outfits look when wet, then press **Install** right below the four cards. **Linking & in-game menu** and **Advanced settings** are folded below the button. The in-game menu list uses the same names and order as the in-game menu, grouped by page, and shows the sync bits each item adds. A progress bar appears while it installs or updates. The [Beginner tutorial](./tutorial.mdx#setup-options) explains what each option means.
- **Purchase activation:** A new install needs purchase activation once per PC. The menu is **CookiTools > RealWetSystem > Purchase Activation**. Uploads from a PC that is not activated leave the effects out, but the build never stops, and the preview and Play still show them. [Purchase activation](./license-activation.mdx)
- **Outfit chooser window:** When you close the install message, a window opens for choosing the outfits that should get wet. **Add Recommended (N)** adds every outfit RealWet is sure about in one go, and **Choose Yourself** lets you pick them one by one. This window doesn't block Unity.
- **Wet look:** Clothes get wet starting where you sweat or where they touch the body. Wet areas take on a deeper color with a watery gloss along the folds, and thin clothes show through. You choose the fabric (cotton · knit · denim, polyester · satin · swimwear, latex · vinyl · enamel, in between) and the strength (subtle, standard, strong). **Even Wet Look for Every Outfit (New Look)** is on by default.
- **lilToon and Poiyomi:** lilToon 2.3.0 or later and Poiyomi Toon / Pro (locked materials included) get wet with the same look.
- **See-Through Protection:** A new install places 4 recommended protection regions on the chest and groin, fitted to the body. Protection regions get wet too; they block only the see-through caused by wetness. They find their spot from the nipple shape key, then the breast bones, then the torso, so they are placed on flat-chested avatars too. [See-through protection](./usage/see-through-protection.mdx)
- **In-game menu:** A **Wet** menu (젖음 in Korean, 濡れ in Japanese) goes into the avatar's main menu. The main page has **Show Clothing Wetness**, **Wetness Amount**, **Whole Area**, **Fast Dry** and **Hold Current State (For Photos)** in this order, followed by the **See-Through Protection** page (the **Private Area Protection** switch and the **See-Through Protection Range** and **See-Through Protection Strength** dials) and the **Wet Tuning** page (with **Maximum Wet Range (%)** in the first slot). The names and order match RealSweatSystem's **Sweat** menu. The recommended set uses 87 bits of synced parameters. [In-game menu](./usage/in-game-menu.mdx)
- **Wet start point and protection region editor:** With **Edit wet / protection regions…**, you move spheres, change their size and spread, and create left-right pairs. The selected sphere's influence shows as color on the body and clothes. [Wet start points](./usage/wet-start-points.mdx)
- **RealSweatSystem linking:** Used together, the clothes get wet following the sweat level on the skin. RealSweatSystem's sweat display applies only to the sweat on the skin; clothing wetness is hidden with **Show Clothing Wetness**.
- **RealRainSystem linking:** Used together, clothes hit by the rain get wet too, and raindrops and streaks are drawn on the same clothes.
- **Builds never stop:** Only the parts RealWet could not apply wetness to are uploaded with their original dry materials, and the NDMF results window shows a warning with the outfit name and the reason. During the upload, the <ProductName /> steps appear in the progress bar.
- **Optimization tools:** The wetness is kept when you build together with AAO, d4rk Avatar Optimizer and TexTransTool. VRCFury works together with it from 1.1436.0. Settings that could remove the wetness are reported ahead of time in the **Other avatar tools** card of the setup window. [Compatibility](./compatibility.mdx#optimizers)
- **Experimental features:** Outfits that use PCSS4VRC (lilToon) or lilSSRT can get wet too. You turn them on per avatar in **Advanced settings > Experimental** in the setup window (off by default). [Advanced features](./advanced.mdx#experimental)
- **Fewer freezes while editing:** Advance preparation runs only while Unity is in the background. Calculations are split up so that Unity doesn't freeze for seconds at a time while you edit registered outfits.
- **Language:** You can choose English / 한국어 / 日本語 for the windows and the in-game menu names.

### Known limitations

- PC only. Quest and mobile are not supported.
- Purchase activation is possible only on Windows. Uploading from Unity on Mac or Linux leaves the <ProductName /> effects out.
- New installs are possible only on Humanoid avatars.
- The layer draw order is not set between separate outfits. Please see [Layer order](./usage/outfit-settings.mdx#layer-order).
- Semi-transparent hair copies whose shader SeeThroughHair changes during the build don't get wet. The rest of the hair gets wet.
- Setups that swap a renderer's mesh itself with an animation are not supported.
- Tools that change the vertex order, the submeshes or the mesh structure of outfit meshes during the upload (anti-ripping tools, polygon reduction tools and so on) may not be compatible. Outfits or parts that no longer match go up dry, and the NDMF build results window shows the reason. [Tools that change outfit meshes](./troubleshooting.mdx#mesh-tools)
- With VRCFury 1.1258 or earlier, the build can show a `SweatAmount` error. Please use VRCFury 1.1436.0 or later.
- Poiyomi 8.x and earlier are not supported.

Other limitations are listed in [Technical specifications](./technical-specifications.mdx#known-limits).

### If you got 1.0.0 before the release {/* #pre-release */}

If you got 1.0.0 before the release, please import the new package over it. Your saved settings stay as they are.

- The names, order and icons of the in-game menu changed. Please press **Update** or **Apply / Update Runtime Menu** once, then build again.
- The **Wet Mode** toggle became **Whole Area**. When on, the whole garment gets wet, and it is off by default. The choice saved for the old **Wet Mode** is not carried over, because its meaning is the opposite.
- **All Clothing Wetness** became **Show Clothing Wetness**, and the **See-Through Protection** toggle became **Private Area Protection**. Only the names changed. **SSAO Relief** is now **Soften Wet Shadows**.
- In Unity, **Restore Recommended In-Game Controls** became **Turn On All Recommended Items**.
