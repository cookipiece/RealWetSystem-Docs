# 互換性

<ProductName />は、インストール時に、必要なパッケージのバージョンと機能を確認します。対応環境でも、衣装・ワードローブ・最適化の設定の組み合わせによって結果が変わることがあるため、アップロードの前に、Build & Testで実際に使う衣装とマテリアルの切り替えを確認してください。

[![RealWetSystemの互換性のまとめ: Poiyomi・lilToonに対応、AAO・d4rk・TexTransToolと一緒にビルド、ビルドが止まらない](/img/booth/booth-compatibility.jpg)](/img/booth/booth-compatibility.jpg)

*<small>互換性のまとめです。詳しくは、下の表を確認してください。</small>*

## 必須パッケージ {/* #requirements */}

| 項目 | 対応範囲 |
| --- | --- |
| Unity | VRChat用のUnity 2022.3プロジェクト |
| VRChat Avatars SDK | 3.10.0以上、4.0未満 |
| NDMF | 1.13.1以上、2.0未満 |
| Modular Avatar | 1.14.0以上、2.0未満 |
| VRCFury（使う場合） | 1.1436.0以上。1.1258以下では、ビルドのときに`SweatAmount`のエラーが出ることがあります。 |
| エディター | WindowsのUnityエディター（購入認証がWindowsでしか動かないため） |
| アバター | Humanoidのアバター（人の形でなくてもかまいません） |
| プラットフォーム | PC専用（Direct3D 11）。Quest・モバイルには対応していません。 |

- 必須パッケージの次のメジャーバージョンのプレリリース版は、対応範囲に含まれません。
- RigがHumanoidに設定されたアバターなら、人の形でなくても使えます。ケモノ・ファーリーのアバターも、ほとんどがHumanoidです。衣装はPoiyomiかlilToonのマテリアルである必要があり、PC専用です。
- Humanoidではないアバターには、新しくインストールできません。モデルのインポート設定で**Rig > Animation Type**を**Humanoid**に変えてから、インストールしてください。
- 自動で置く濡れ開始点と透け保護の範囲は、体の形によっては合わないことがあります。[濡れる場所や透け保護の位置がアバターに合わない](./troubleshooting.mdx#placement-mismatch)
- パッケージをインポートした後に**CookiTools**メニューがない場合や、Missing Scriptが表示される場合は、[スクリプトが壊れて見える、またはCookiToolsメニューがない](./troubleshooting.mdx#scripts-missing)を確認してください。
- 同じアバターをQuest（Android）向けにビルドすると、ゲーム内メニュー、同期パラメーター、FXレイヤーは入りますが、服は濡れません。ビルドは止まりません。メニューとパラメーターを節約するには、Quest用に別に作ったアバターのコピーから<ProductName />を削除してください。
- バージョンが合わない場合は、どのパッケージがないか、または更新が必要かを、インストール画面が知らせます。<ProductName />が他のパッケージを自動で更新することはありません。

## シェーダー {/* #shaders */}

シェーダーは、衣装が実際に使うものだけをインストールすれば大丈夫です。Poiyomiの衣装だけを使うなら、lilToonは必要ありません。

### Poiyomi Toon / Pro

| 項目 | 内容 |
| --- | --- |
| 対応するバリエーション | 基本形、**Outline Early**、**Two Pass**、**Fade**モード |
| 試験したバージョン | Poiyomi 9.3、10.0.9、10.0.24、Pro 11.0.0、11.0.18、11.0.22、11.0.24、11.0.29、11.0.32、11.0.34、11.0.35、11.0.36、11.0.38 |
| ロックされたマテリアル | 元のシェーダーの情報を確認できれば濡れます。アップロード時にThryがロックする場合も同じです。 |
| 対応していないもの | Poiyomi 8.x以下、Fur、Grab Pass、名前だけ似ているカスタム拡張版、パッケージの外にコピーしたシェーダー、別のシェーダーモジュールを入れたPoiyomi |

- Poiyomi 8.x以下の衣装は濡れません。衣装の画面に、対応していないシェーダーとして表示されます。
- <ProductName />は、バージョン番号ではなく、シェーダーの構造を直接確認します。そのため、上の表にないバージョンでも、構造が同じなら濡れます。インストールされているバージョンの構造が<ProductName />の知っているものと違う場合は、NDMFの結果ウィンドウに、**まだ確認されていない Poiyomi のバージョン**という警告が、バージョンごとに1つ表示されます。そのシェーダーを使う衣装は濡れなしでビルドされ、ビルドは続行されます。
- Poiyomiマテリアルの**Third Party**一覧（以前のPoiyomi 11では**Poi > Installed Modules**）に表示される「RealWet内部用、インストールしないでください」は、インストールしないでください。インストールすると、Poiyomiの服が濡れなくなります。すでにインストールした場合は、[元に戻す方法](./troubleshooting.mdx#poi-internal-module)に従ってください。
- VRCFuryはアップロード中にマテリアルをコピーするとき、プロジェクトの中のロックされていないPoiyomiマテリアルをロックすることがあります。これはVRCFuryの動作で、濡れには影響しません。編集を続けるには、Poiyomiのインスペクターでロックを解除してください。

### lilToon

| 項目 | 内容 |
| --- | --- |
| 対応バージョン | 正式版のlilToon 2.3.0以上（2.3.4で試験） |
| 対応モード | 通常、**Multi / MultiOutline**（不透明・カットアウト・半透明） |
| 制限付きで対応 | **Refraction / RefractionBlur**: 濡れた色・光沢だけを加えます。元の透明度・屈折・レンダーキューはそのままで、追加の透けは入れません。 |
| 対応していないもの | Fur、Gem、ユーザーが改変したシェーダー |

lilToonで反射（Reflection）とメタリックをオンにしたマテリアルでも、濡れた光沢は消えません。

### 実験機能：PCSS4VRC（lilToon）・lilSSRT {/* #experimental */}

PCSS4VRC（lilToon、10.1.5で確認）とlilSSRT（1.4.3）の衣装も、実験機能で濡らせます。インストール画面の**詳細設定 > 実験機能**でアバターごとにONにします。初期はOFFです。オンとオフの違いは、[高度な機能](./advanced.mdx#experimental)を確認してください。

### 対応していないシェーダー

Sunao、UnityChanToon、UTSなど、別系統のシェーダーには濡れを入れません。その部分は元の見た目のままアップロードされます。<ProductName />が、元のマテリアルのシェーダーを別の系統に変えることはありません。

## Modular AvatarとNDMF {/* #ma-ndmf */}

- 一般的な衣装の導入やメニューの統合は、そのまま使えます。<ProductName />は、ビルドの過程で衣装に濡れを付けます。
- ゲーム内メニューは、**RealWet**オブジェクトのMA ParametersとMA Menu Installerで追加します。メニューファイルは、`Assets/CookiTools/Generated/RealWet/RuntimeMenus`にアバターごとに作られます。
- 服の中の体をMA Shape Changerで隠している衣装は、**この衣装でMA Shape Changerが隠したBodyを再表示**をオンにすると、濡れて透けたときに体が見えます。初期値はオフです。オンにすると、乾いた状態でも体が残ります。
- Unityのプレビューは、NDMFのプレビューを使います。**Tools > NDM Framework > Enable Previews**がオンになっている必要があります。

### Write Defaults

インストール画面の**Write Defaults**は、特に指示がなければ**自動**を使ってください。アバターのFXを読み取って、<ProductName />の値を決めます。アバターの制作者が特定の値を求めている場合だけ、ONまたはOFFを手動で選んでください。

## 最適化ツール {/* #optimizers */}

他のツールがビルド中に衣装を結合したり変更したりしても、<ProductName />は最終的な衣装に合わせて確認します。エラーがなければ、衣装全体をあらかじめ最適化から外す必要はありません。濡れが消えるおそれのある設定は、インストール画面の**他のアバターツール**欄で事前に知らせます。

対応している最適化ツールは、下の表の**AAO**、**d4rk Avatar Optimizer**、**TexTransTool**です。アップロード中に衣装メッシュの頂点の順番、サブメッシュ、メッシュの構造を変えるツール（裂け防止ツール、ポリゴン削減ツールなど）は、互換性がないことがあります。そのようなツールのせいで濡れのデータと合わなくなった衣装やパーツは、乾いたままアップロードされ、NDMFのビルド結果ウィンドウに理由が残ります。ビルドは止まりません。[衣装メッシュを変えるツール](./troubleshooting.mdx#mesh-tools)

| ツール | 併用するとき |
| --- | --- |
| **AAO (Avatar Optimizer)** | Trace and Optimizeは、そのまま使ってかまいません。自動のメッシュ結合が一緒に処理できないパーツどうしを結合するときだけ、<ProductName />が片方を自動で結合から外し、お知らせします。**Optimize Animator**がパラメーターの形式を変えても、濡れのトグルはそのまま動きます。**Merge Skinned Mesh**で、異なる衣装のパーツやボディを結合すると、そのメッシュは濡れません。衣装のボディが結合されると、インストール画面がお知らせします。衣装ごとに別々に結合し、ボディは結合から外してください。 |
| **TexTransTool (TTT)** | TTTでテクスチャを変えたPoiyomiマテリアルも、アップロードで濡れます。**Atlas Texture**がマテリアルを1つにまとめると、基準になるマテリアルのスロットは濡れ、別のマテリアルにまとめられたスロットだけが濡れません（NDMFの結果ウィンドウでお知らせします）。そのスロットも濡らすには、そのマテリアルを結合グループから外してください。 |
| **d4rk Avatar Optimizer** | 基本設定（Basic）なら、そのままにします。シェーダーを書き換える設定（**Write Properties as Static Values**、**Shader Toggles**、**Merge Different Property Materials**、**Merge Same Dimension Textures**）がオンの場合は、アップロード時に、濡れるパーツだけをd4rkから自動で外します。保存された設定は変更しません。インストール画面では、これらの設定をオフにすることをおすすめしています。 |
| **VRCFury** | 1.1436.0以上を使ってください。1.1258以下では、ビルドのときに`SweatAmount`のエラーが出ることがあります。トグルとマテリアルの切り替えは、そのまま使えます。最初からオンのトグルと**Apply During Upload**が入れるマテリアルも濡れます。切り替わるマテリアルが濡れない場合は、NDMFの結果ウィンドウに案内が出ます。 |
| **ボーンを動かすツール** | ビルド中に別のツールがボーンを動かしても（例：NDExtensionsのRebake Humanoid）、アップロードでプレビューと同じ位置が濡れます。 |

アニメーションでRendererの**メッシュそのもの**を切り替える構成には、対応していません。メッシュを切り替えるアニメーションを外すか、切り替わるメッシュを、<ProductName />から除外した別のRendererに分けてください。

### ほかの濡れツール

1つの衣装に、<ProductName />とほかの濡れツールを一緒に使わないでください。2つのツールが衣装メッシュの同じUVチャンネル（UV6）を使うと、片方の濡れが消えたり崩れたりすることがあります。<ProductName />はほかの濡れツールを検出しないため、1つの衣装には濡れツールを1つだけ使ってください。

## RealSweatSystemとの併用 {/* #realsweat */}

同じアバターにRealSweatSystemがあると、<ProductName />が検出します。新規インストールでは**RealSweat連動**がオンの状態で始まり、肌の最終的な汗の量に、服も従います。

| したいこと | 設定 |
| --- | --- |
| 動いて汗をかいたら、服も濡れる | RSSの自動モードと**RealSweat連動**をオンにします。 |
| 肌は乾いたままにして、服だけを濡らす | **RealSweat連動**をオフにして、<strong>濡れ量（連動OFF時）</strong>を上げます。 |
| また肌の汗に従わせる | **RealSweat連動**をオンにします。 |

- Unityで初期値を変えるには、**RealWet**の**入力モード**の行で、**連動する**または**連動解除**を選びます。
- <ProductName />で連動を切り替えても、肌の汗の量は変わりません。
- RealSweatSystemの**汗の表示**と**自分にだけ表示**は、肌の汗にだけ適用されます。衣装の濡れは、<ProductName />の<strong>衣装の濡れを表示</strong>と衣装別表示でだけ隠します。
- **濡れ**メニューは、RSSのメニューの中ではなく、アバターのメインメニューに独立して追加されます。
- RealSweatSystem 2.0.0のLate Queueの汗シェーダーも肌の汗として認識し、濡れた服をボディと汗の後に描きます。
- 選んだアバターのRealSweatSystemが旧バージョン（1.x）の場合は、インストール画面に更新の案内が1行出ます。

## RealRainSystemとの併用 {/* #realrain */}

RealRainSystem（RealRain）と一緒に使うと、雨粒・水の筋・光沢が、<ProductName />の濡れシェーダーの上に一緒に描かれます。雨の設定はRealRainで変更します。

- 雨で衣装が濡れる効果は、<ProductName />が描きます。RealRainだけをインストールすると、天気（雲・雨・雨音）は動きますが、衣装は濡れません。
- 2つのツールは別々に販売し、購入認証もツールごとに行います。
- RealRainで問題が起きると、<ProductName />は雨だけをオフにし、濡れはそのままにします。ビルドは止まりません。
- 雨を受ける服の頂点ごとに、<ProductName />がUV6に番号を書いておきます。そのため、最適化ツールが頂点の番号を振り直しても、雨は正しい位置に表示されます。メッシュにすでにUV6のデータがある場合は、そのレンダラーの雨だけをオフにしてお知らせします。

- <strong>綿・ニット・デニム（おすすめ）</strong>の生地には、RealRainは雨粒と光沢を描きません（水を吸う布だからです）。
- **濡れた感じの強さ**が**強め**で、生地がなめらかな種類の場合は、雨粒の光沢も少し明るくなります。
- lilToonの**Multi**と**Refraction**のマテリアル枠は雨の効果を受けず、通常の濡れだけが適用されます。
