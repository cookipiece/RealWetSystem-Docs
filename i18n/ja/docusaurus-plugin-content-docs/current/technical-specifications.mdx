# 技術仕様と既知の制限

このページでは、<ProductName /> v1.0.2がアバターに何をどのように加えるかを、数字でまとめます。普通に使うだけなら、読まなくてもかまいません。

## 対応環境 {/* #environment */}

| 項目 | 対応範囲 |
| --- | --- |
| エディター | WindowsのUnityエディター（購入認証がWindows専用のため） |
| Unity | VRChat用のUnity 2022.3 |
| VRChat Avatars SDK | 3.10.0以上、4.0未満 |
| NDMF | 1.13.1以上、2.0未満 |
| Modular Avatar | 1.14.0以上、2.0未満 |
| シェーダー | lilToon 2.3.0以上（2.3.4で試験）、Poiyomi Toon / Pro（試験したバージョンは[互換性](./compatibility.mdx#shaders)） |
| アバター | Humanoidのアバター。Humanoidでない場合、新規インストールはできません。 |
| プラットフォーム | Direct3D 11を使うPCアバター。Quest・モバイルには対応していません。 |

## 動作のしくみ {/* #how-it-works */}

- 濡れる位置、広がり、保護マスク、体までの距離は、Unityで事前に計算して、メッシュとテクスチャに入れます。
- ゲームの中では、濡れシェーダーがそのデータとメニューの値を読み取って描画します。パーティクル、PhysBone、Collider、Contactは追加しません。
- プレビューとアップロードは、同じ設定と同じ計算を使います。
- NDMFプラグインの名前は**RealWetSystem**です。

## 同期パラメーター {/* #parameters */}

選んだメニュー項目のパラメーターだけが、アバターに入ります。

| メニュー | パラメーター | 同期 | 保存 | 初期値 |
| --- | --- | --- | --- | --- |
| 衣装の濡れを表示 | `Cooki/ClothWetEnable` | 1ビット | 保存する | オン |
| 濡れ量（RealSweatSystemなしで使うとき） | `Cooki/ClothWetAmount` | 8ビット | 保存する | 0% |
| RealSweat連動 | `Cooki/ClothWetSweatLink` | 1ビット | 保存する | オン |
| 濡れ量（連動OFF時） | `Cooki/ClothWetManualAmount` | 8ビット | 保存する | 0% |
| 全範囲濡れ | `Cooki/ClothWetWhole` | 1ビット | 保存する | オフ |
| 高速乾燥 | `Cooki/ClothWetFastDry` | 1ビット | 保存しない | オフ |
| 現在の状態を固定（撮影用） | `Cooki/ClothWetHold` | 1ビット | 保存しない | オフ |
| 自分にだけ表示（RealSweatSystemなしで使うとき） | `Cooki/ClothWetLocalOnly` | 1ビット | 保存する | オフ |
| 大事な部分の透け防止 | `Cooki/ClothWetProtect/All` | 1ビット | 保存しない | Unityの設定値（新規インストールはオン） |
| 透け防止の範囲（50%=標準） | `Cooki/ClothWetProtectRange` | 8ビット | 保存する | 50% |
| 透け防止の強さ（100%=完全に防ぐ） | `Cooki/ClothWetProtectStrength` | 8ビット | 保存する | 100% |
| 最大の濡れ範囲（%） | `Cooki/ClothWetProgressLimit` | 8ビット | 保存する | Unityの設定値 |
| 濡れ表現（50%=標準） | `Cooki/ClothWetAppearance` | 8ビット | 保存する | 50% |
| 濡れ光沢（50%=標準） | `Cooki/ClothWetGloss` | 8ビット | 保存する | 50% |
| 透け強度（50%=標準） | `Cooki/ClothWetSeeThroughStrength` | 8ビット | 保存する | 50% |
| 濡れ透けモード | `Cooki/ClothWetSeeThroughModeV2` | 8ビット | 保存する | 設定どおり |
| 濡れの境界 | `Cooki/ClothWetEdgeSoftness` | 8ビット | 保存する | 50% |
| 濡れた服の影を軽減 | `Cooki/ClothWetSsaoRelief` | 1ビット | 保存する | オン |
| 衣装ごとの違いを減らす | `Cooki/ClothWetOutfitCorrection` | 1ビット | 保存する | Unityの設定値（新規インストールはオン） |
| 濡れる範囲を広げる（上級者向け） | `Cooki/ClothWetRangeExpansion` | 8ビット | 保存する | 0% |
| 衣装別表示のグループ | `Cooki/ClothWetGroup…` | グループごとに1ビット | — | オン |

表は、ゲーム内のメニューの順番（メインページ、**透け防止**、**濡れ調整**）に従っています。

- おすすめメニューは87ビット、衣装別表示のグループ6個まですべて入れると94ビットです。VRChatの上限は、アバター全体で256ビットです。
- RealSweatSystemと連動するときは、RSSの汗のパラメーター（`Cooki/SweatAmount`など）を読み取るだけです。RSSのパラメーターは変えません。
- メニューに入れていない機能は、Unityで決めた値で動き、パラメーターを追加しません。
- メニューの1ページは8枠です。**濡れ調整**に9個以上入ると、7個の後に**次へ**のページができます。<strong>濡れる範囲を広げる（上級者向け）</strong>は、いつも最後の枠です。

## アニメーター {/* #animator */}

- アップロードするとき、FXに`Cooki Clothing Wetness/`で始まるレイヤーを加えます。レイヤー数は、選んだメニュー項目によって変わります。
- MA Merge Animatorは使いません。アバターの他のFXレイヤーと元のコントローラーは変更しません。
- Write Defaultsが**自動**のときは、アバターのFXを読み取って合わせます。
- **衣装ごとの違いを減らす**と**最大の濡れ範囲**のダイヤルを一緒に入れると、FXに出力グループごとの事前計算した補正クリップが増えます。同期ビットとゲーム内の計算は増えません。最大の濡れ範囲は、0・5・10・20・40・60・80・100%とUnityの初期値では計算した値のとおりで、その間の値は、近い2つの段階を混ぜた近似です。

## レンダーキュー {/* #render-queue */}

レンダーキューは、描画の順番を決める数字です。小さい値が先に、大きい値が後に描かれます。<ProductName />は、濡れ用コピーのレンダーキューだけを変えます。

| 元のキュー | 濡れ用コピーのキュー |
| --- | --- |
| 不透明・カットアウト、および2499以下の半透明 | 「ボディ・肌の汗のキュー + 1」から2499の間 |
| 2501〜2999（半透明） | 同じ範囲の中でだけ後ろへ |
| 3000〜3099（半透明） | 同じ範囲の中でだけ後ろへ |
| それ以外の半透明（2500、3100以上） | そのまま |

- たとえば、RealSweatSystem 2.0.0の汗が2350なら2351〜2499、ボディだけで2000なら2001〜2499です。
- ボディのキューを読み取れないときは、2460〜2499を使い、お知らせします。
- 不透明と半透明の境界を越えて動かしません。入れる余地が足りないときは動かさず、NDMFの結果ウィンドウでお知らせします。
- 実験機能PCSS4VRC(lilToon)を使うパーツは、PCSSの影を保つため、2499を超えません。
- 手動の順序（**手動: 描画優先度を指定**）は、0〜39の範囲です。

## メッシュとテクスチャのデータ {/* #mesh-data */}

| データ | 入れる場所 |
| --- | --- |
| 濡れのデータ（位置、広がり、保護） | メッシュのTEXCOORD2・TEXCOORD3（設定画面のUV3・UV4）のうち、空いている方。両方とも使用中なら、テクスチャに入れます。 |
| RealRainの雨の頂点番号 | TEXCOORD6（UV6）。すでにUV6を使っているメッシュは、そのレンダラーの雨だけをオフにします。 |
| ブレンドシェイプ連動の濡れの2つ目の状態 | UV3/UV4 |
| 保護マスク | テクスチャ（保護範囲までの距離を入れ、シェーダーでなめらかにぼかします） |

- 濡れるパーツは、メッシュのコピーを作ってデータを加えます。元のメッシュ・FBXとインポート設定は変更しません。
- <ProductName />が保存するメッシュは圧縮しません。FBXでMesh Compressionをオンにした衣装は、そのメッシュだけ非圧縮のサイズでアップロードされます。
- PC（D3D11）では、シェーダーの1パスで使えるテクスチャは64個までです。アップロードの最終的なシェーダーがこの上限を超えると、そのマテリアルだけが元の乾いたマテリアルに戻ります。

## 上限 {/* #limits */}

| 項目 | 上限 |
| --- | --- |
| アバター共通の濡れ開始点 | 64個 |
| アバター共通の保護範囲 | 64個 |
| ゲーム内の衣装別表示のグループ | 6個 |
| 保護範囲の**縁をやわらかく** | 0〜5 cm |
| 開始点の**ポイントの半径** | 半径0.5〜15 cm |

## 作るファイル {/* #generated-files */}

| ファイル | 場所 |
| --- | --- |
| 濡れシェーダー | `Assets/CookiTools/RealWetSystem/Generated`（パスが長すぎる場合は`Assets/RWGen`） |
| アバターごとのメニューファイル | `Assets/CookiTools/Generated/RealWet/RuntimeMenus` |
| 計算キャッシュ | プロジェクトの`Library/RealWet` |

- 削除されても、必要なときに作り直します。キャッシュのフォルダーを先に削除する必要はありません。
- 実験機能が作るシェーダーは、このPCにインストールされている他の作者のシェーダーから作ったものです。エクスポートしたり、配布したりしないでください。

## 既知の制限 {/* #known-limits */}

- 対応していないシェーダー（Sunao、UnityChanToon、UTS、Poiyomi 8.x以下、PoiyomiのFur・Grab Pass、lilToonのFur・Gem、ユーザーが改変したシェーダー）には、濡れを入れません。
- アップロード中に衣装メッシュの頂点の順番、サブメッシュ、メッシュの構造を変えるツール（裂け防止ツール、ポリゴン削減ツールなど）は、互換性がないことがあります。合わなくなった衣装やパーツは乾いたままアップロードされ、NDMFのビルド結果ウィンドウに理由が残ります。AAO、d4rk Avatar Optimizer、TexTransToolには対応しています。
- VRCFury 1.1258以下では、ビルドのときに`SweatAmount`のエラーが出ることがあります。1.1436.0以上を使ってください。
- lilToonのRefraction / RefractionBlurは、濡れた色・光沢だけを加え、追加の透けは入れません。
- 異なる衣装どうしの重ね着の順序は決めません。
- アニメーションでRendererの**メッシュそのもの**を切り替える構成には、対応していません。
- 濡れ開始点の球を1つずつゲーム内でオン・オフする機能はありません。
- ブレンドシェイプ連動の濡れは、今の服の形だけを表示し、服が動く前の位置の濡れは覚えていません。
- `_TransparentMode`の数値だけをアニメーションで変えるlilToonのモード切り替えまでは、保証しません。
- SDKの前処理コールバックを呼ばない別のエクスポートツールでは、アップロードの最後のテクスチャ上限の復旧が適用されないことがあります。
