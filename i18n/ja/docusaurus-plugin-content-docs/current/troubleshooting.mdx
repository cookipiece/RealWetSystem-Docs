## インストールボタンがグレー {/* #install-gray */}

1.0.0では、次の場合に**インストール**ボタンがグレーになり、その理由が画面に表示されません。1.0.1からはボタンの上に理由が表示され、1つ目の場合もUnpackせずにインストールできます。

| 原因 | 解決 |
| --- | --- |
| アバターがFBX（モデルファイル）をそのままシーンに置いたものです。Unityはこのようなアバターを編集できないモデルとして扱います。 | 先にシーンを保存します。ヒエラルキーでアバターを右クリック →「**Prefab > Unpack Completely**」を押してから、インストールウィンドウの「**更新**」を押してください。 |
| 「**アバター**」欄にProjectウィンドウのプレハブファイルが入っています。 | ヒエラルキーでアバターをクリックしてから、インストールウィンドウの「**検出**」を押してください。 |
| UnityがPlay中です。 | Playを終了してから、もう一度お試しください。 |

それでもグレーのままの場合は、ヒエラルキーが見えるUnity画面全体をBOOTHのメッセージで送ってください。

## スクリプトが壊れて見える、またはCookiToolsメニューがない {/* #scripts-missing */}

パッケージをインポートしたのに、Unityのメニューバーに**CookiTools**がない場合や、`RealWet`オブジェクトや衣装のコンポーネントが**Missing Script**と表示される場合は、次を順に確認してください。Missing Scriptになったコンポーネントは削除しないでください。原因を直すと元に戻ります。

### 1. 必須パッケージがない、または古い {/* #scripts-packages */}

VCCの**Manage Project**で次のパッケージを確認し、対応範囲内の最新バージョンに更新してください。

| パッケージ | 対応範囲 |
| --- | --- |
| VRChat Avatars SDK | 3.10.0以上、4.0未満 |
| NDMF | 1.13.1以上、2.0未満 |
| Modular Avatar | 1.14.0以上、2.0未満 |
| VRCFury（使う場合） | 1.1436.0以上 |

- 新しいメジャーバージョン（例: 2.0）が出ている場合は、上げる前に[互換性](./compatibility.mdx#requirements)を確認してください。対応範囲外のバージョンでは、<ProductName />の本体が読み込まれません。
- VRChat Avatars SDK、NDMF、Modular Avatarのどれかがない場合や対応範囲外の場合は、パッケージをインポートした後やUnityを起動した後に、**RealWet Dependencies**ウィンドウが一度開きます。パッケージごとに、**インストールが必要**、**更新が必要**などの状態と対応範囲が表示されます。
- このウィンドウには、ボタンが3つあります。表示言語をまだ選んでいない場合は、英語で表示されます。
  - **再確認**（Check Again）: パッケージを変えた後に、もう一度確認します。
  - **問い合わせ情報をコピー**（Copy Issue for Support）: Unityとパッケージのバージョンをコピーします。自動では送信しません。
  - **VCC ヘルプ**（VCC Help）: VRChatのVCCの案内ページを開きます。
- この状態で**CookiTools > RealWetSystem > Setup／Uninstall**を押すと、インストール画面の代わりに**RealWet — インストール互換性確認**の案内が出ます。アバターは変更されません。
- NDMFがまったくない場合は、`RealWet`オブジェクトと衣装の<ProductName />コンポーネントが、Missing Scriptと表示されます。
- <ProductName />が、パッケージを自動で更新することはありません。
- VRCFuryは、このウィンドウでは確認しません。古いVRCFuryでは、ビルドのときにエラーが出ます。[VRCFuryが古い](#vrcfury-old)

### 2. ほかのパッケージに赤いコンパイルエラーがある {/* #scripts-compile-error */}

どのパッケージでも、赤いコンパイルエラーが1つでもあると、Unityは新しくインポートしたツールを読み込めません。そのため、メニューもコンポーネントも動かず、上の確認ウィンドウも開きません。

1. **Window > General > Console**を開きます。
2. いちばん上にある、最初の赤いエラーを探します。
3. エラーに表示されたファイルのパスから、どのパッケージかを確認し、そのパッケージを更新するか削除します。

### 3. VRChat用のUnity 2022.3プロジェクトではない {/* #scripts-unity-version */}

VCCで作成した、VRChat用のUnity 2022.3のアバタープロジェクトで使ってください。

### 4. インポートした直後 {/* #scripts-after-import */}

インポートした直後にConsoleに赤いエラーが残っている場合は、Unityを一度再起動してください。[以前のバージョンの上から更新する](#updating)にも、同じ案内があります。

### 5. パッケージの一部だけをインポートした {/* #scripts-partial-import */}

インポート画面で一部のファイルのチェックを外してインポートすると、動かないことがあります。`.unitypackage`をもう一度インポートし、すべての項目にチェックを入れたまま**Import**を押してください。

解決すると、Unityのメニューバーに**CookiTools**が表示されます。このPCで初めて使う場合は、まず[購入認証](./license-activation.mdx)を行ってください。

それでも解決しない場合は、Consoleの最初の赤いエラーの全文と、VCCの**Manage Project**のパッケージ一覧（名前とバージョン）を一緒に送ってください。[問い合わせる](#support)

## 衣装が濡れない {/* #outfit-dry */}

| 原因 | 解決 |
| --- | --- |
| 衣装が登録されていません。 | **RealWet > 衣装管理**の一覧に、その衣装があるか確認します。なければ、**今すぐ検索**か**手動で追加**で追加します。 |
| 衣装やパーツの**濡れ機能を使用**がオフになっています。 | **この衣装の設定**と**衣装パーツ設定**の上部にあるチェックをオンにします。 |
| 髪や小物のように、体から離れたパーツです。 | **汗をかく所から**は、開始点の近くだけが濡れます。髪は、ふつうは濡れないのが正常です。濡らすには、ゲーム内の**全範囲濡れ**をオンにするか、その近くに[開始点](./usage/wet-start-points.mdx)を追加します。 |
| <strong>最大の濡れ範囲 (%)</strong>が低いか、<strong>この素材の濡れ表現 (%)</strong>が0%です。 | [濡れ設定](./usage/wet-settings.mdx#range)と、パーツのスロットカードを確認します。 |
| 対応していないシェーダーです。 | パーツカードに<strong>RealWet が対応していないシェーダー（…）のため、このパーツは濡れません。</strong>と表示されます。[互換性](./compatibility.mdx#shaders)を確認してください。 |
| ビルドでだけ濡れません。 | NDMFの結果ウィンドウの警告を見ます。[NDMFの警告](#ndmf-warnings)を確認してください。 |
| アップロードしたアバター全体で効果がありません。 | [購入認証せずにアップロードした](#not-activated)を確認してください。 |

**透けなし**の衣装は、体が透けないのが正常です。色と光沢が変わるかどうかで、濡れを確認してください。保護範囲は濡れを防がず、透けだけを防ぎます。

## 一部だけ濡れない {/* #partly-dry */}

| 原因 | 解決 |
| --- | --- |
| 汗が届かない所です（袖の先、スカートの裾など）。 | 正常です。範囲を上げるか、その近くに開始点を追加するか、**全範囲濡れ**を使います。 |
| 体から遠く離れた、ゆったりした布です。 | そのパーツの**フィットプリセット**を**密着**に変えます。 |
| そのパーツのマテリアルだけが、対応していないシェーダーです。 | そのパーツは元の見た目のまま残ります。対応シェーダーに変えるか、そのままにします。 |
| ワードローブのアニメーションで切り替わるマテリアルだけが濡れません。 | **この衣装の設定 > 問題解決 > 追加で準備する切替マテリアル**に、そのマテリアルを入れます。 |
| 最適化ツールがパーツを結合したり、コピーしたりしました。 | NDMFの結果ウィンドウに**RealWet: 一部のパーツのみ濡れ効果なしでビルドされました**と表示されます。下の表を確認してください。 |
| 衣装の一部を、衣装ルートの外に移しました。 | 衣装ルートの下に戻すと、また濡れます。ビルドのときに、移した部分の名前がコンソールに残ります。 |

## プレビューでは濡れるのに、ビルド・再生・アップロードで濡れない {/* #preview-ok-build-dry */}

プレビューでは濡れるのに、Build & Test、再生（Play）、アップロードで濡れない場合は、たいていビルドのときに、ほかのツールや環境が結果を変えています。次の順で原因を探してください。

1. ビルドや再生の後に、NDMFの結果ウィンドウを見ます。ウィンドウが閉じている場合は、**Tools > NDM Framework > Show NDMF Console**で開きます。<ProductName />が濡れ効果なしにした衣装やパーツは、名前と理由が`RealWet:`で始まる警告として残ります。エラーの全文はConsoleにあります。
2. 下の表から当てはまるケースを探し、右の項目を確認してください。

| どこで濡れないか | よくある原因 | 見る所 |
| --- | --- | --- |
| アップロードしたアバターでだけ、効果がまったくない。プレビューと再生は正常 | このPCが購入認証されていません。NDMFの警告は出ず、Consoleに1行だけ残ります。 | [購入認証せずにアップロードした](#not-activated) |
| 再生のときだけ、一部の衣装が乾いている | まだ準備できていない衣装があるか、再生を始めたときにアバターがオフでした。 | [再生すると一部の衣装が濡れない](#play-not-ready) |
| アップロードでだけ、一部のlilToonパーツが乾いている（PCSS4VRCを使用） | PCSS4VRCが、ビルドの最初の段階でマテリアルを差し替えました。 | [PCSS4VRCがマテリアルを差し替える](#pcss) |
| 裂け防止・ポリゴン削減ツールを使った衣装だけが乾いている | そのツールが衣装メッシュを変えました。 | [衣装メッシュを変えるツール](#mesh-tools) |
| ほかのツールを通ったパーツだけが乾いている | ほかのツールがパーツを作ったり、コピー・分割・結合したり、マテリアルを差し替えたり書き換えたりしたため、<ProductName />が認識できませんでした。 | [ほかのツールがビルド中にマテリアルを変えた](#material-replaced)、[NDMFの警告](#ndmf-warnings)の**一部のパーツのみ濡れ効果なしでビルドされました**、**どの衣装か判断できず、濡れ効果なしのままにしたパーツがあります**、d4rkの行 |
| アップロードしたアバターで、濡れマテリアルやメニューの値が変わっている | アップロードの最後に動くツール（例: VRCFury Parameter Compressor）が、結果を変えました。 | [NDMFの警告](#ndmf-warnings)の**アップロードの後の段階で RealWet の結果が変更されました** |
| アニメーション、MA Material Setter、Material Swapで切り替えたマテリアルだけが乾いている | その切り替え先のマテリアルが準備されていません。 | [一部だけ濡れない](#partly-dry)の**追加で準備する切替マテリアル** |
| 特定のバージョンのPoiyomiの衣装だけが乾いている | まだ確認されていないシェーダーのバージョンです。 | [対応していない、または確認されていないシェーダー](#shaders) |
| 警告の理由に、Unityがコンパイル・インポート中だったと書かれている | ビルドを始めたときに、Unityがスクリプトのコンパイルやアセットのインポート中だったか、別のRealWetの処理を実行中でした。 | 終わってから、もう一度ビルドします。[NDMFの警告](#ndmf-warnings) |
| Quest（Android）のビルドで、服が濡れない | <ProductName />はPC専用です。 | [互換性](./compatibility.mdx#requirements) |

どれにも当てはまらない場合は、**診断レポートをコピー**でコピーしたレポートと、NDMFの結果ウィンドウの`RealWet:`の行を一緒に送ってください。[問い合わせる](#support)

## ほかのツールがビルド中にマテリアルを変えて濡れない {/* #material-replaced */}

プレビューでは濡れるのに、アップロードすると特定の衣装だけ濡れない場合は、ビルド中にほかのツールがその衣装のマテリアルを差し替えたり、コピーしたりしている可能性があります。<ProductName />は登録したマテリアルだけを濡らします。ほかのツールが作ったマテリアルは無理に濡らさず、元の見た目のままにします。ビルドは止まらず、ほかの衣装は濡れます。

原因は次の手順で調べます。

1. 一度ビルド（または Build & Test）してから、アバターの`RealWet`オブジェクトを選び、インスペクターの**状態 > 問題解決 > 診断レポートをコピー**を押します。
2. コピーしたレポートをメモ帳に貼り付け、下のほうの`[Recent RealWet console lines]`で、濡れなかった衣装やパーツの名前が出ている行を探します。マテリアル名も一緒に出ています。
   - `Material 'Towel White_FSS' referenced by default on 'Bath Towel' slot 0 is unsupported`：ビルド中に入ったマテリアルのシェーダーに対応していません。
   - `Final material 'Shirt_clone' cannot be traced to captured material 'Shirt'`：ビルド中に作られたコピーなので、元の衣装のマテリアルか確認できません。
3. その行のマテリアル名を、シーンでそのパーツに入っているマテリアル名と比べます。名前が違ったり、後ろに文字が付いていたり（`_FSS`、`_clone`など）すれば、ビルド中にほかのツールがマテリアルを変えています。

解決方法:

- そのマテリアルを作ったツールを探して無効にするか、その衣装（パーツ）をツールの対象から外します。もう一度ビルドすると、元のマテリアルで濡れます。
- ただし、そのツールの効果はその衣装には付かなくなります。どちらを使うか決めてください。
- どのツールか分からない場合は、レポートを[問い合わせる](#support)から送ってください。

## 濡れる場所や透け保護の位置がアバターに合わない {/* #placement-mismatch */}

<ProductName />は、いろいろなアバターで使えるように汎用的に作っていますが、アバターの体の形やボーンの位置によっては、自動で置いた球が合わないことがあります。その場合は、球の位置と範囲を自分で調整してください。

| 症状 | 解決 |
| --- | --- |
| 関係ない所が濡れる、または汗をかく所が濡れない。 | その近くの濡れ開始点の球を、Sceneで移動し（W）、サイズを変えます（R）。[エディターを開く](./usage/wet-start-points.mdx#editor)、[よく使う調整](./usage/wet-start-points.mdx#tips) |
| 透け保護の範囲が胸・股からずれている、または小さすぎる・大きすぎる。 | 保護範囲をSceneで移動し（W）、回転し（E）、サイズを変えます（R）。[保護範囲を編集する](./usage/see-through-protection.mdx#editing) |
| 左右を一緒に直したい。 | どちらのエディターにも**左右対称**があります。オンにして、片側だけを直します。 |
| 最初の配置に戻したい。 | 開始点は[元に戻す・配置し直す](./usage/wet-start-points.mdx#reset)、保護範囲は[初期化ボタン](./usage/see-through-protection.mdx#reset)を使います。 |

- 直した後は、プレビューを50%と100%で確認してください。
- 保護範囲は、[確認する方法](./usage/see-through-protection.mdx#checking)のように、前・横・後ろから確認してください。
- 濡れ始める方式が**体に触れる所から**のときは開始点を使わないため、球を動かしても、濡れる場所は変わりません。ゲーム内の**全範囲濡れ**がオンのときも同じです。

## 重ね着が消える、または順序がおかしい {/* #layer-issues */}

濡れて透ける服は、体・下着・上着を描く順序（レンダーキュー）が合っていないと、自然に見えません。<ProductName />は衣装ごとに重なり方を見て、順序を自動で決めますが、すべての重ね着を検出できるわけではありません。検出できなかったパーツは、同じキューになったり、順序が逆になったりして、濡れたときに内側の服が消えたように見えることがあります。

まず、その衣装の**この衣装の設定 > 衣装パーツ > 重ね着の描画順序 · レンダーキュー**を開いてください。使い方は[重ね着の順序](./usage/outfit-settings.mdx#layer-order)にあります。次に、下から当てはまるケースを探してください。

### 同じ衣装の中の下着が、角度によって消える {/* #layer-same-queue */}

- **原因:** 接しているか重なっている2つのパーツが、同じキューです。この場合はどちらを先に描くかをUnityが決めるため、濡れたときに内側の服が消えることがあります。パーツどうしが交差している、くっつきすぎている、パーツが多くて判断の根拠が足りない、といった場合にこうなります。
- **見分け方:** 順序一覧に**同じキュー**の表示が出ます。ビルドの後は、NDMFの結果ウィンドウに**RealWet: 重ね着の描画順を確認してください**が表示されます。検出できなかった場合は、表示も警告も出ないことがあります。
- **解決:** 一覧で2つのパーツのどちらかをドラッグし、内側を上に、外側を下に置きます。表示が出ていなくても、同じ方法で直します。
- 髪の影のように、同じメッシュをもう一度描くマテリアルは、ベースのすぐ後に自動で置きます。影が別のオブジェクトの場合は、一覧でベースより下にドラッグしてください。

### 別に登録したアウターや髪の下で、内側の服が消える {/* #layer-other-outfit */}

- **原因:** 順序は衣装ごとに別々に決めます。異なる衣装どうしの順序は決めないため、別に登録したアウターが、下の服より先に描かれることがあります。ワードローブでオン・オフするアウターを、別の衣装として登録した場合も同じです。
- **解決:** アウターの衣装のスロットを**手動: 描画優先度を指定**に変えて、大きい数値（例: 20）を指定するか、アウターを下の服と同じ衣装として一緒に登録します。
- 同じ衣装の中では、アップロード時にオフで、ゲーム内でオンにするパーツも、同じ順序になります。
- アバターの基本衣装がメッシュごとに別々に登録されている場合、1つの衣装にまとめる方法は、[アバターの基本衣装は衣装単位でまとめる](./usage/outfit-settings.mdx#group-base-clothes)にあります。

### マテリアルを切り替えた状態や、最適化ツールを使った後だけおかしい {/* #layer-swapped */}

- **原因:** アニメーション、MA Material Setter、Material Swapで切り替えたマテリアルは、描画方式（不透明・カットアウト、または半透明）が元と同じなら、元の順序を使います。描画方式が違うと、その描画区間の先頭に置かれます。最適化ツールがパーツを変えて、元のどのパーツか判断できない場合も先頭に置きます。順序の異なるパーツをまとめた場合は、その中で最も内側の順序を使います。
- **見分け方:** 最適化ツールが原因の場合は、ビルドの後、NDMFの結果ウィンドウかコンソールに、パーツ名と一緒に**マテリアルの描画区間が変わりました**、**元のどのパーツか判断できませんでした**、**最も内側の順序を使います**などの行が残ります。
- **解決:** 切り替え先のマテリアルは、元のマテリアルと同じ描画方式にそろえてください。Build & Testで切り替えた状態も確認し、ほかのパーツと同じキューになったという警告が出た場合は、順序一覧でドラッグします。切り替え先のマテリアルだけが濡れない場合は、[一部だけ濡れない](#partly-dry)を確認してください。

### 「マテリアルのRender Queueを維持」のスロットがある {/* #layer-preserve */}

- **原因:** **マテリアルのRender Queueを維持**は、以前の設定です。順序を計算せず、濡れ用コピーの基本のキューをそのまま使います。不透明・カットアウトの服はすべて同じキュー（2460）になるため、重なったパーツの前後はUnityが決めます。この場合、ビルドの警告は出ません。
- **見分け方:** 衣装のすべてのスロットがこの設定の場合は、順序一覧に**この衣装はすべてのスロットがマテリアルのキューを維持しています（以前の設定）。**と表示されます。
- **解決:** **自動の順序にする**を押すか、そのスロットを**衣装表面から自動判定**に変えます。Ctrl+Zで元に戻せます。

### 描画区間が違うため、順序を合わせられない {/* #layer-bands */}

- **原因:** 不透明・カットアウトの服と半透明の服は、描く区間が違います。<ProductName />は、パーツを別の区間へ移しません。そのため、内側の服が半透明で上着が不透明だと、内側の服が後に描かれることがあります。体や肌の汗のキューが2499に近く、服を入れる余地が足りない場合も、元のキューのままにします。
- **見分け方:** NDMFの結果ウィンドウに、**…の描画区間のほうが後に描かれます**、または**…入れる余地がないため、次のパーツは元のキューのままです**と表示されます。
- **解決:** <ProductName />は、元のマテリアルと体を変更しません。2つの服の描画方式をそろえるかどうかは、ご自身で決めてください。そのスロットに**直接: レンダーキューを指定**を使うこともできますが、区間をまたぐ数値では深度や影が変わることがあるため、プレビューで確認してください。

### 登録していないパーツと重なる {/* #layer-unmanaged */}

- **原因:** <ProductName />に登録していないパーツ（ストッキング、レースなど）の順序は変えません。そのパーツのキューが2460より低い場合は、濡れた服をその後に描きます。順序一覧の上に**RealWet が変更しない … の後**と表示されます。2460以上の場合は順序を合わせないため、濡れた服の下で消えたり、上に見えたりすることがあります。
- **解決:** そのパーツを同じ衣装に一緒に登録すると、一緒に順序を決めます。濡れた見た目が必要ない場合は、そのスロットの<strong>この素材の濡れ表現 (%)</strong>を0%にします。

### レンダーキューを変えた後、ほかの服がおかしくなった {/* #layer-side-effects */}

:::caution[レンダーキューを変えると、ほかの服の見た目も変わることがあります]
レンダーキューは、アバター全体で描く順序です。1つの衣装の数値を変えると、その前後に描かれる飾り、透明効果、ほかの衣装との重なりも変わることがあります。

- <ProductName />は、元のマテリアルのレンダーキューを変更しません。変わるのは、プレビューとアップロードに使う濡れ用コピーのキューだけです。ただし、ゲーム内ではそのコピーが描かれるため、見える順序は変わります。
- 服の制作者がレンダーキューの数値で見た目を合わせている衣装（ステンシル、レース、透明効果など）は、順序が変わると見た目も変わることがあります。自動の順序も、濡れ用コピーの数値を決め直します。
- 手動・直接の数値を指定すると、同じ衣装の自動のパーツはその数値を避けるため、ほかのパーツの数値も動くことがあります。
- 手動の数値は、同じボディを使う衣装どうしで、同じ基準で数えます。大きい数値を指定すると、ほかの衣装のパーツより後に描かれます。
- ドラッグと**直接: レンダーキューを指定**は、固定の数値です。後でボディやRealSweatが変わっても、それに合わせて動きません。

変えた後は、プレビューで前・横・後ろを確認してください。変えたくなかったスロットは、**衣装表面から自動判定**に戻します。衣装全体は、**重ね着の順序を自動に戻す**でまとめて戻せます。服の制作者が決めた数値の順序を守る必要がある衣装では、同じ画面の**内側 → 外側の判定を優先**をオフにします。すると、元のマテリアルのキューの順序を先に守り、同じキューどうしだけを内外で分けます。透明効果のマテリアルのように、制作者の数値をそのまま使う必要があるスロット1つだけに、**マテリアルのRender Queueを維持**を使うこともできます。不透明・カットアウトの服には使わないでください。
:::

## ピンクのマテリアル {/* #pink */}

| 原因 | 解決 |
| --- | --- |
| 元のマテリアルの時点で、シェーダーがない（Missing）か、ピンクです。 | <ProductName />とは関係ありません。まず、衣装の制作者が指定したシェーダーをインストール・復元します。 |
| シェーダーの1パスのテクスチャが64個を超えました。 | そのマテリアルで使っていないテクスチャ機能（MatCap、発光、デカールなど）を減らしてから、ビルドし直します。[テクスチャの上限](#texture-limit) |
| d4rkが濡れシェーダーを結合して書き換えました。 | d4rkの**Write Properties as Static Values**、**Shader Toggles**、**Merge Different Property Materials**、**Merge Same Dimension Textures**をオフにするか、そのパーツをd4rkのExclusionsに入れます。 |
| シェーダーを更新した直後で、キャッシュが合っていません。 | プレビューかビルドを、もう一度行います。必要なシェーダーは、自動で準備し直します。先にキャッシュのフォルダーを削除する必要はありません。 |

<ProductName />は、ピンクになる可能性があるパーツを隠しません。服を隠すと、体が見えてしまうことがあるためです。その代わりに、NDMFの結果ウィンドウに警告を残します。

## 購入認証せずにアップロードした {/* #not-activated */}

認証していないPCからアップロードすると、<ProductName />の効果が、アップロードから何も知らせずに外れます。ビルドは失敗せず、ウィンドウも出ません。

- Unityのプレビューと再生（Play）では、濡れた見た目がそのまま表示されます。アップロードしたアバターでだけ外れます。
- Consoleに、`RealWetSystem：このPCは購入認証されていないため、アップロード時に…の効果が外れます。`で始まる警告が1行残ります。
- インストール画面のアバター欄のすぐ下に、案内と**認証ウィンドウを開く**ボタンが表示されます。
- RealRainの雨で服が濡れる様子も<ProductName />が描いているため、一緒に外れます。

**解決:** **CookiTools > RealWetSystem > Purchase Activation**で認証してから、アップロードし直してください。[購入認証](./license-activation.mdx)

## PCSS4VRCがマテリアルを差し替える {/* #pcss */}

PCSS4VRCを使うアバターでは、PCSS4VRCがビルドの最初の段階で、lilToonマテリアルを`_pcss`マテリアルに差し替えます。そのため、プレビューで濡れたパーツが、アップロードでは濡れないことがあります。

- このようなパーツは、衣装・パーツのプレビューの上に**アップロード時、この部分は濡れません**という案内と、すぐにオンにするボタンが表示され、ビルドのときにNDMFの警告1つで知らせます。
- **解決:** インストール画面の**詳細設定 > 実験機能**で<strong>PCSS4VRC(lilToon)</strong>の対応をオンにして、**更新**を押します。これで、PCSSの衣装も濡れます。実験機能なので、先に[高度な機能](./advanced.mdx#experimental)を読んでください。
- PCSS4VRCがシェーダーを差し替えないlilToonのユーザーシェーダーを使うパーツは、アップロードでも濡れます。
- 実験機能をオンにしても、PCSS4VRCがlilToonの**Multi**・**MultiOutline**（およびTessellation・Lite）系統を差し替えたパーツは濡れず、NDMFの警告が表示されます。1.0.0の警告は機能をオンにするよう案内することがありますが、すでにオンならこの系統が原因です。そのマテリアルをlilToonの標準シェーダーに変えるか、PCSS4VRCの変換対象から外してください。

## VRCFuryが古い {/* #vrcfury-old */}

VRCFuryを一緒に使うアバターで、ビルドのときに`SweatAmount`という言葉を含むエラーが出る場合は、VRCFuryが古い版の可能性があります。1.1258以下のVRCFuryで、このエラーが確認されています。

**解決:** VCCでVRCFuryを**1.1436.0以上**に更新してから、ビルドし直してください。VRCFuryを使わないアバターには当てはまりません。

## 衣装メッシュを変えるツール {/* #mesh-tools */}

アップロード中に衣装メッシュの頂点の順番、サブメッシュ、メッシュの構造を変えるツールは、<ProductName />と互換性がないことがあります。裂け防止（アンチリッピング）ツールやポリゴン削減ツールが、その例です。

- <ProductName />は、濡れのデータを衣装メッシュに合わせて入れます。ほかのツールがメッシュを変えて合わなくなった衣装やパーツは、濡れなしで乾いたままアップロードされます。
- ビルドは止まりません。NDMFのビルド結果ウィンドウに、その衣装（またはパーツ）の名前と理由が警告として残ります。
- AAO（Avatar Optimizer）、d4rk Avatar Optimizer、TexTransToolには対応しています。[互換性](./compatibility.mdx#optimizers)を確認してください。
- その衣装を濡らすには、そのツールの対象から濡れる衣装を外して、ビルドし直してください。

## 対応していない、または確認されていないシェーダー {/* #shaders */}

| 場合 | 結果と解決 |
| --- | --- |
| Sunao、UnityChanToon、UTSのような他の系統 | 濡れを入れずに、元の見た目でアップロードされます。 |
| Poiyomi Fur、Grab Pass、パッケージの外にコピーしたPoiyomi、名前だけが似ているカスタムシェーダー | 元の見た目のままにします。 |
| lilToon Fur、Gem、ユーザーが改造したlilToon | 元の見た目のままにします。 |
| lilToon Refraction / RefractionBlur | 濡れた色と光沢だけを加えます。追加の透けは入れません。 |
| まだ確認されていないPoiyomiのバージョン | そのシェーダーを使う衣装だけが乾いたままビルドされ、NDMFの警告が出ます。<ProductName />の更新をお待ちください。 |
| ロックされた（Locked）Poiyomiマテリアル | 元のシェーダーの情報が見つかれば濡れます。見つからない場合は、案内が出ます。 |
| Poiyomiの**Third Party**一覧（以前のPoiyomi 11では**Poi > Installed Modules**）で、<ProductName />の内部モジュールをインストールした | インストールしないでください。インストールすると、Poiyomiの服が濡れません。[元に戻す方法](#poi-internal-module) |

試験したシェーダーのバージョンは、[互換性](./compatibility.mdx#shaders)にあります。

## PoiyomiでRealWetの内部モジュールをインストールした {/* #poi-internal-module */}

Poiyomiマテリアルのインスペクターの**Third Party**一覧（以前のPoiyomi 11では**Poi > Installed Modules**）に、「RealWet内部用、インストールしないでください」が表示されます。<ProductName />が濡れシェーダーを作るときに使うモジュールなので一覧に表示され、これは正常です。インストールしないでください。インストールすると、Poiyomi本体のシェーダーに<ProductName />のコードが入り、<ProductName />はそのシェーダーを使う衣装を濡らさずにビルドします。ビルドは止まりません。

すでにインストールした場合は、次の手順で元に戻します。

- **Third Party一覧があるPoiyomi**
  1. Poiyomiのマテリアルを1つ選択します。
  2. インスペクターの**Third Party**見出しの右にある**⋮**メニューを開きます。
  3. **Remove RealWet**で始まる項目をすべて押します。Poiyomiがそのシェーダーを作り直します。
  4. ほかのPoiyomiシェーダーを使うマテリアルも、シェーダーごとに1つずつ選択します。Poiyomiがそのシェーダーも作り直します。
- **Poi > Installed ModulesメニューがあるPoiyomi**
  1. 上部メニューの**Poi > Installed Modules**を開きます。
  2. 「RealWet内部用、インストールしないでください」（以前の名前は`Cooki Clothing Wetness`）のチェックを外します。
  3. **Apply & Rebuild Shaders**を押します。

もう一度ビルドすると、Poiyomiの衣装がまた濡れます。

## 1つのシーンにアバターが複数ある {/* #multiple-avatars */}

<ProductName />は、アバターごとに別々に動作します。同じシーンにアバターが複数あっても、互いの設定を使うことはありません。

- アバターごとに、別々にインストールする必要があります。インストール画面の**アバター**欄で、今選んでいるアバターが正しいか確認してください。
- 1つのアバターに`RealWet`オブジェクトが2つ以上あると、**重複エラー**が表示されます。1つだけ残してください。
- 他のアバターからコピーしてきた衣装が、そのアバターのボディやボーンを指している場合は、何がどのアバターを指しているかと、直し方をプレビューが知らせます。
- 2つ目のアバターで最初に確認したのが、髪のように、もともと濡れにくいパーツではないか確認してください。シャツのように体に触れる服で先に確認すると、違いがわかりやすくなります。
- NDMF・Modular Avatarは、正式版で確認しています。試験版（ベータ）を使っている場合は、正式版に替えてから、もう一度確認してください。

## 保存していない新しいシーン {/* #unsaved-scene */}

<strong>アバターに安定したシーン識別子がありません。シーンを保存してからもう一度お試しください。</strong>と表示された場合は、アバターが、まだ一度も保存していない新しいシーン（Untitled）にある、という意味です。

**解決:** **File > Save**でシーンを保存してから、もう一度インストールまたはプレビューしてください。

## 最初のビルドに時間がかかる {/* #long-first-build */}

初めてビルドするときや、初めてプレビューするときは、濡れシェーダーを作り、Unityがコンパイルします。マテリアルが多いアバターでは、**数十分**かかることがあります。このとき、Unityのウィンドウがほとんど動かず、止まったように見えることがあります。

{/* SHOT U28: build progress bar */}

1. **お待ちください。** アップロード中は、`RealWet: 衣装の形状を計算中 (3/22) · 衣装名`のように、段階と順番、衣装名が進行表示に出ます。Unity自体のシェーダーのコンパイル中は、進行表示が長い間そのままのことがあり、ウィンドウなしで進むこともあります。
2. **タスクマネージャーでCPUを確認します。** Unityや`UnityShaderCompiler`がCPUを使っていれば、まだ処理中です。終了せずに待ってください。
3. CPUが数分間ほぼ0%で、進行表示も変わらないときだけ、止まったと判断します。そのときは、Consoleの最初の赤いエラーと、待った時間を記録して問い合わせてください。

- 2回目のビルドからは、最初のビルドで作ったシェーダーのキャッシュを使い回すため、ずっと短くなります。
- 配信や録画のようにPCが忙しいときは、さらに時間がかかります。最初のビルドは、PCが空いているときに済ませておくのがおすすめです。
- **RealWet > 衣装管理 > 必要な衣装のみ準備**で、ビルドの前に準備しておけます。
- インストール画面の**インストール**・**更新**と、再生（Play）に初めて入るときにも、進行状況バーが表示されます。今している作業が表示されている間は、お待ちください。

詳しい時間は、[パフォーマンス](./performance.mdx#build-time)を確認してください。

## 最初のアップロードに時間がかかる {/* #first-upload */}

最初のアップロードでは、最初のビルドと同じシェーダーの準備に加えて、VRChat SDKのシェーダーのコンパイルと、アップロードファイルの圧縮があるため、時間がかかります。

- 濡れるマテリアルごとに濡れシェーダーが入るため、アップロードファイルが大きくなり、圧縮にも時間がかかります。[パフォーマンス](./performance.mdx#upload-size)を確認してください。
- アップロードのときに、Poiyomiがマテリアルをロックする時間も加わります。
- 同じ設定なら、2回目のアップロードからは短くなります。

## Hold onウィンドウ {/* #hold-on */}

Unityの**Hold on**ウィンドウは、Unityが処理を終えるまで待ってほしい、という意味です。

| いつ | 原因と解決 |
| --- | --- |
| 最初のプレビュー、最初のビルド、シェーダーを更新した直後 | 濡れシェーダーを準備しています。お待ちください。 |
| パッケージをインポートした直後 | Unityがスクリプトとシェーダーをインポートしています。お待ちください。 |
| Unityを前面に出したまま、何もしていないとき | <ProductName />は、Unityが背面にあるときだけ事前に準備します。それでも出る場合は、他のツールやUnity自体の処理かもしれません。 |
| 他のアプリを使ってから、Unityに戻ったとき | 事前の準備を止めるための、短い時間です。途中で止められないシェーダーの準備は、Unityが3分以上背面にあるときだけ始めます。 |

同じ操作で**Hold on**が何度も長く出る場合は、その操作とConsoleの内容を記録して問い合わせてください。

## メニュー・パラメーターが上限を超える {/* #over-limit */}

VRChatでは、1つのアバターで同期パラメーターを**256ビット**まで使えます。<ProductName />のおすすめメニューは87ビットです。RealSweatSystemや他のツールと合わせて上限を超えると、VRChat SDKがアップロードを止めます。

1. **RealWet > ゲーム内メニュー**の**最終同期コスト**で、<ProductName />が使う量を確認します。
2. 使わないダイヤルのチェックを外します。ダイヤルは1つにつき8ビット、トグルは1ビットです。たとえば、**濡れる範囲を広げる**、**濡れの境界**、**濡れ表現**を外すと、24ビット減ります。
3. **ゲーム内メニューを適用 / 更新**を押して、ビルドし直します。

- ボタンを外した機能は、Unityで決めた値のまま動き続けます。
- メニューの1ページは8枠です。<ProductName />は、枠が足りないと**次へ**のページを作り、メインメニューは増やしません。
- VRCFury Parameter Compressorのような、パラメーターを圧縮するツールを使うこともできます。圧縮ツールが濡れのパラメーターを変えた場合は、NDMFの結果ウィンドウでお知らせします。

## メニューが見当たらない {/* #menu-missing */}

1. メインメニューで**濡れ**（英語は**Wet**、韓国語は**젖음**）を探します。
2. メニューの場所を変えた場合は、`RealWet`オブジェクトの**MA Menu Installer**に指定したメニューの中を確認します。
3. **RealWet > ゲーム内メニュー**で、**ゲーム内メニューを適用 / 更新**を押します。
4. ビルドし直して、そのアバターを確認します。ビルドが失敗していた場合は、前のアバターを見ている可能性があります。

- メニューファイルがなくなった場合は、保存されたシーンを開いたときに、<ProductName />が作り直して接続します。コンソールに<strong>RealWet のゲーム内メニューファイルがなかったため、RealWet が作り直してつなぎました。シーンを保存してください。</strong>と残るので、シーンを保存してください。
- メニューを手動で移動したり、別のメニューに置き換えたりした場合、<ProductName />はそのメニューをそのままにします。作り直すには、`RealWet`オブジェクトの**MA Menu Installer**を削除してから、**ゲーム内メニュー**タブの**ゲーム内メニューを修復**を押してください。
- メニューが別の言語で表示される場合は、Unityで使いたい言語を選んでからメニューを更新し、ビルドし直してください。
- メニューのボタンはあるのに、アイコンだけがない場合は、パッケージの`Icons`フォルダーをインポートし直してから、メニューを更新してください。機能はそのまま使えます。

## 再生すると一部の衣装が濡れない {/* #play-not-ready */}

再生ボタンを押したときに、まだ準備ができていない衣装があると、<ProductName />は再生を少し待たせて、その衣装を準備します。準備が終わると、再生が自動で始まります。

{/* SHOT U29: Game view overlay before Play */}

- 待っている間に再生ボタンをもう一度押すと、すぐに始まります。このとき、準備ができていない衣装は、その再生でだけ濡れません。
- 再生を終えると、その衣装から準備し、次の再生から濡れます。
- 再生を始めたときにオフで、再生中にオンにしたアバターは、その再生では濡れません。アバターをオンにした状態で、もう一度再生してください。

## テクスチャの上限 {/* #texture-limit */}

PC向けのUnityとVRChatでは、シェーダーの1パスが使うテクスチャは64個までしか描画できません。機能を多くオンにしたPoiyomiマテリアルは、プレビューではロックする前のシェーダーを使うため、濡れを加えると、この上限を超えることがあります。

- そのようなスロットは、ピンクではなく元の見た目でプレビューし、案内を表示します。
- VRChatのPC向けアップロードでは先にシェーダーをロックするため、このスロットは、たいてい濡れた状態でアップロードされます。
- アップロードの最終的なシェーダーも上限を超える場合は、そのマテリアルだけが元の乾いたマテリアルに戻ります。アップロードは止まりません。
- 濡れを保つには、そのマテリアルで使っていないテクスチャ機能（MatCap、発光、デカールなど）を減らしてから、ビルドし直してください。

## 登録済みの衣装が0件 {/* #no-outfits */}

1. インストールしたアバターの下にある`RealWet`を選んでいるか確認します。
2. **衣装管理 > 自動で探す > 今すぐ検索**を押します。
3. 漏れた服は、**手動で追加**にHierarchyの衣装ルートを入れて、**追加**を押します。

- `EditorOnly`の衣装は、初期設定では探しません。
- 衣装ルートがボディ・顔のメッシュオブジェクトの中にあると、登録されないことがあります。[衣装設定](./usage/outfit-settings.mdx)を確認してください。
- <strong>×</strong>で削除した衣装は、自動ではもう一度追加しません。手動で追加してください。

## プレビューの問題

| 症状 | 解決 |
| --- | --- |
| まったく始まらない | **Tools > NDM Framework > Enable Previews**がオンか、Edit Modeかを確認します。 |
| 時間がかかる | Inspectorの現在の段階を確認します。最初は、シェーダーの準備のために時間がかかります。ボタンを押し直す必要はありません。 |
| **一時停止中 · Unityに戻ってください** | 他のアプリに切り替えただけです。Unityに戻ると続きます。 |

| 準備が必要だと何度も表示される | 開始方式、範囲、衣装の形、シェーダーを変えると、準備し直します。何も変えていないのに繰り返す場合は、衣装名と理由を記録して問い合わせます。 |

## 以前のバージョンの上から更新する {/* #updating */}

1. 更新する前に、プロジェクトをバックアップしてください。
2. `Assets/CookiTools/RealWetSystem`フォルダーは削除せず、新しいパッケージを、その上にそのままインポートしてください。先にアンインストールする必要はありません。
3. インポートした直後にConsoleに赤いエラーが残っている場合は、Unityを一度再起動してください。
4. インストール画面で、アバターごとに**更新**を押します。
5. 最初にプレビューまたはビルドするときは、濡れシェーダーを準備し直すため、1回だけ時間がかかります。

- 保存された設定、開始点、保護範囲は、そのまま残ります。
- 手を加えていない以前の標準の見た目だけが、1回だけ新しい標準の見た目に変わります。このとき、**RealWet > 衣装管理**に、お知らせと<strong>元に戻す…</strong>が表示されます。
- 保存された開始点の配置が新しいおすすめの配置と違う場合は、更新のときに**濡れ開始点をリセット** / **既存の設定を維持**を尋ねます。よくわからない場合は、**既存の設定を維持**を選んでください。
- 新しいおすすめの保護の形を使うには、[更新した後の保護範囲](./usage/see-through-protection.mdx#after-update)を確認してください。

詳しい手順は、[更新履歴](./update-changelog.mdx#how-to-update)にあります。

## アンインストール {/* #uninstall */}

- **衣装を1つだけ外す:** **RealWet > 衣装管理**のその衣装の行で<strong>×</strong>を押すか、**濡れ機能を使用**をオフにします。服そのものは残ります。
- **アバターからすべて外す:** **CookiTools > RealWetSystem > Setup／Uninstall**の**アンインストール**タブで、**アンインストール**を押します。確認ウィンドウで**アンインストール**を押すと、`RealWet`オブジェクトとその下の内容、衣装の<ProductName />コンポーネント、このインストールのメニューファイルを片付けます。衣装・ボディ・元のマテリアルは残ります。確認ウィンドウにも書かれているとおり、削除はCtrl+Zで元に戻せません。
- `RealWet`オブジェクトの下には、他の衣装やツールを入れないでください。アンインストールのときに、一緒に削除されます。
- 最初のインストール、全体のアンインストール、ゲーム内メニューの作成・更新・削除は、Ctrl+Zで元に戻せません。
- プロジェクトからパッケージまで削除するには、すべてのアバターで先に**アンインストール**をしてから、`Assets/CookiTools/RealWetSystem`フォルダーを削除してください。
