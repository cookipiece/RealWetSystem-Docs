# トラブルシューティング

まず、下の表で症状を探してください。問題が繰り返す場合は、複数の設定を一度に変えるより、衣装1つで確認するほうが原因を見つけやすくなります。

## 衣装が濡れない {/* #outfit-dry */}

| 原因 | 解決 |
| --- | --- |
| 衣装が登録されていません。 | **RealWet > 衣装管理**の一覧に、その衣装があるか確認します。なければ、**今すぐ検索**か**手動で追加**で追加します。 |
| 衣装やパーツの**濡れ機能を使用**がオフになっています。 | **この衣装の設定**と**衣装パーツ設定**の上部にあるチェックをオンにします。 |
| 髪や小物のように、体から離れたパーツです。 | **汗をかく所から**は、開始点の近くだけが濡れます。髪は、ふつうは濡れないのが正常です。濡らすには、ゲーム内の**全範囲濡れ**をオンにするか、その近くに[開始点](./usage/wet-start-points.mdx)を追加します。 |
| <strong>最大の濡れ範囲 (%)</strong>が低いか、<strong>この素材の濡れ表現 (%)</strong>が0%です。 | [濡れ設定](./usage/wet-settings.mdx#range)と、パーツのスロットカードを確認します。 |
| 対応していないシェーダーです。 | パーツカードに<strong>RealWet が対応していないシェーダー（…）のため、このパーツは濡れません。</strong>と表示されます。[互換性](./compatibility.mdx#shaders)を確認してください。 |
| ビルドでだけ濡れません。 | NDMFの結果ウィンドウの警告を見ます。[NDMFの警告](#ndmf-warnings)を確認してください。 |
| アップロードしたアバター全体で効果がありません。 | [購入認証せずにアップロードした](#not-activated)を確認してください。 |

**透けなし**の衣装は、体が透けないのが正常です。色と光沢が変わるかどうかで、濡れを確認してください。保護範囲は濡れを防がず、透けだけを防ぎます。

## 一部だけ濡れない {/* #partly-dry */}

| 原因 | 解決 |
| --- | --- |
| 汗が届かない所です（袖の先、スカートの裾など）。 | 正常です。範囲を上げるか、その近くに開始点を追加するか、**全範囲濡れ**を使います。 |
| 体から遠く離れた、ゆったりした布です。 | そのパーツの**フィットプリセット**を**密着**に変えます。 |
| そのパーツのマテリアルだけが、対応していないシェーダーです。 | そのパーツは元の見た目のまま残ります。対応シェーダーに変えるか、そのままにします。 |
| ワードローブのアニメーションで切り替わるマテリアルだけが濡れません。 | **この衣装の設定 > 問題解決 > 追加で準備する切替マテリアル**に、そのマテリアルを入れます。 |
| 最適化ツールがパーツを結合したり、コピーしたりしました。 | NDMFの結果ウィンドウに**RealWet: 一部のパーツのみ濡れ効果なしでビルドされました**と表示されます。下の表を確認してください。 |
| 衣装の一部を、衣装ルートの外に移しました。 | 衣装ルートの下に戻すと、また濡れます。ビルドのときに、移した部分の名前がコンソールに残ります。 |

## NDMFの警告 {/* #ndmf-warnings */}

<ProductName />が原因でビルドが止まることはありません。濡れを適用できなかった部分だけが元の乾いたマテリアルでアップロードされ、NDMFの結果ウィンドウに警告が残ります。エラーの全文は、UnityのConsoleにあります。保存された濡れ設定と元のマテリアルは変わらず、次のビルドでもう一度試します。

{/* SHOT U27: NDMF window with a RealWet warning */}

| NDMFの警告 | 意味 | すること |
| --- | --- | --- |
| **RealWet: 一部の衣装は濡れ効果なしでビルドされました**（アップロード中は<strong>…アップロードされます</strong>、再生中は**RealWet: 今回の Play では一部の衣装が濡れ効果なしで表示されます**） | 名前が表示された衣装だけが、濡れも雨もなしでアップロードされます。他の衣装は正常です。 | 警告の理由を見ます。ビルドのときにUnityがコンパイル中だった場合は、終わってからビルドし直せば大丈夫です。理由がわからない場合は、診断レポートをコピーして問い合わせます。 |
| **RealWet: 一部のパーツのみ濡れ効果なしでビルドされました** | 他のツールがパーツを作ったり、コピー・分割・結合したりしたか、アニメーションが濡れないマテリアルに切り替えます。そのパーツ（またはその状態）だけが乾きます。 | 警告に表示されたツールの設定を確認します。オプティマイザーが複数の衣装を1つのメッシュに結合した場合は、そのメッシュを結合から外すか、同じ衣装としてまとめます。 |
| **RealWet: 一部のパーツがすべての人にマゼンタ（ピンク）で表示されることがあります** | 元のマテリアルに戻せないパーツがあります。隠さずに、ビルドが残したとおりにしておきます。 | [ピンクのマテリアル](#pink)を確認してください。 |
| **RealWet: まだ確認されていない Poiyomi のバージョン（…）です** | インストールされているPoiyomiの構造が、<ProductName />が知っているものと違います。そのシェーダーを使う衣装は、乾いたままビルドされます。 | このビルドは、そのまま使ってかまいません。<ProductName />の更新を待つか、確認済みのPoiyomiのバージョンを使います。 |
| **RealWet: シェーダーモジュール「…」が追加された Poiyomi にはまだ対応していません** | Poiyomiの**Poi > Installed Modules**でオンにしたモジュールが、シェーダーに入っています。Poiyomiの衣装が、乾いたままビルドされます。 | そのモジュールをオフにして、ビルドし直します。 |
| **RealWet: PCSS4VRC が差し替えたマテリアルのパーツは濡れずにアップロードされます** | PCSS4VRCが、ビルドの最初の段階でlilToonマテリアルを`_pcss`マテリアルに差し替えました。 | [PCSS4VRCがマテリアルを差し替える](#pcss)を確認してください。 |
| **RealWet: 重ね着の描画順を確認してください** | 前後が決まっていない重ね着のパーツがあります。ビルドは止まっていません。 | その衣装の**計算された順序 · 内側 → 外側**の一覧で、名前が表示されたパーツを1つドラッグします。[重ね着の順序](./usage/outfit-settings.mdx#layer-order) |
| **RealWet: 一部のパーツを AAO の自動メッシュ結合から外しました** | お知らせです。AAOが一緒に処理できないパーツどうしを結合しないように、片方を外しました。 | 直すことはありません。メッシュの数が少し増えることがあります。 |
| **RealWet: d4rk Avatar Optimizer が書き換えた濡れるパーツを元に戻せませんでした** | d4rkのシェーダーを書き換える設定が、濡れるパーツを変えました。 | そのd4rkの設定をオフにするか、パーツをd4rkのExclusionsに入れて、アップロードし直します。 |
| **RealWet: 一部の衣装で雨の濡れをオフにしました** | RealRainの雨のデータを、そのスロットで使えませんでした。通常の濡れはそのままです。 | 警告の`[vertex order changed]`・`[no vertex index]`・`[not verified]`の説明に従います。たいていは、RealWetとRealRainを最新版に更新すれば解決します。 |
| **RealWet: 一部のパーツで濡れ機能の一つをオフにしました** | ポーズによる濡れのような機能を1つだけ、今回のビルドでオフにしました。通常の濡れはそのままです。 | 警告の理由に従います（例: ブレンドシェイプが他のツールで変わった）。 |
| **RealWet: アップロードの後の段階で RealWet の結果が変更されました** | アップロードの最後に動くツール（例: VRCFury Parameter Compressor）が、濡れマテリアルやパラメーターを変えました。 | ゲーム内で確認し、おかしい場合は、診断レポートをコピーして問い合わせます。 |
| **RealWet: どの衣装か判断できず、濡れ効果なしのままにしたパーツがあります** | お知らせです。他のツールが作ったパーツのため、どの衣装のものか判断できませんでした。 | 濡れるべきパーツなら、そのパーツを作ったツールを確認します。 |
| **RealWet: アップロード最後の確認を実行できませんでした** / **RealWet: 最後の濡れ漏れ確認を完了できませんでした** | それより前の確認は通っていて、アップロードは続きます。その後の変更は確認できませんでした。 | アップロードしたアバターで衣装を確認します。 |
| `Could not check the D3D11 texture limit` | シェーダーのテクスチャの数を確認できませんでした。 | [テクスチャの上限](#texture-limit)を確認してください。 |

- これらの警告で、ビルドが止まることはありません。ビルドが止まった場合は、Consoleの**最初の赤いエラー**を別に確認してください。最後の`Build was aborted`だけでは、原因はわかりません。
- アップロード中に衣装メッシュを変えるツールを一緒に使うと、その衣装やパーツがこの警告とともに乾いたままアップロードされることがあります。下の[衣装メッシュを変えるツール](#mesh-tools)を確認してください。
- ボディを再表示した衣装（**この衣装でMA Shape Changerが隠したBodyを再表示**）が乾いたままアップロードされると、動いたときにボディが服の外に見えることがあります。警告にも、そのように書かれます。ボディを隠すには、そのオプションをオフにしてから、ビルドし直してください。

## ピンクのマテリアル {/* #pink */}

| 原因 | 解決 |
| --- | --- |
| 元のマテリアルの時点で、シェーダーがない（Missing）か、ピンクです。 | <ProductName />とは関係ありません。まず、衣装の制作者が指定したシェーダーをインストール・復元します。 |
| シェーダーの1パスのテクスチャが64個を超えました。 | そのマテリアルで使っていないテクスチャ機能（MatCap、発光、デカールなど）を減らしてから、ビルドし直します。[テクスチャの上限](#texture-limit) |
| d4rkが濡れシェーダーを結合して書き換えました。 | d4rkの**Write Properties as Static Values**、**Shader Toggles**、**Merge Different Property Materials**、**Merge Same Dimension Textures**をオフにするか、そのパーツをd4rkのExclusionsに入れます。 |
| シェーダーを更新した直後で、キャッシュが合っていません。 | プレビューかビルドを、もう一度行います。必要なシェーダーは、自動で準備し直します。先にキャッシュのフォルダーを削除する必要はありません。 |

<ProductName />は、ピンクになる可能性があるパーツを隠しません。服を隠すと、体が見えてしまうことがあるためです。その代わりに、NDMFの結果ウィンドウに警告を残します。

## 購入認証せずにアップロードした {/* #not-activated */}

認証していないPCからアップロードすると、<ProductName />の効果が、アップロードから何も知らせずに外れます。ビルドは失敗せず、ウィンドウも出ません。

- Unityのプレビューと再生（Play）では、濡れた見た目がそのまま表示されます。アップロードしたアバターでだけ外れます。
- Consoleに、`RealWetSystem：このPCは購入認証されていないため、アップロード時に…の効果が外れます。`で始まる警告が1行残ります。
- インストール画面のアバター欄のすぐ下に、案内と**認証ウィンドウを開く**ボタンが表示されます。
- RealRainの雨で服が濡れる様子も<ProductName />が描いているため、一緒に外れます。

**解決:** **CookiTools > RealWetSystem > Purchase Activation**で認証してから、アップロードし直してください。[購入認証](./license-activation.mdx)

## PCSS4VRCがマテリアルを差し替える {/* #pcss */}

PCSS4VRCを使うアバターでは、PCSS4VRCがビルドの最初の段階で、lilToonマテリアルを`_pcss`マテリアルに差し替えます。そのため、プレビューで濡れたパーツが、アップロードでは濡れないことがあります。

- このようなパーツは、衣装・パーツのプレビューの上に**アップロード時、この部分は濡れません**という案内と、すぐにオンにするボタンが表示され、ビルドのときにNDMFの警告1つで知らせます。
- **解決:** インストール画面の**詳細設定 > 実験機能**で<strong>PCSS4VRC(lilToon)</strong>の対応をオンにして、**更新**を押します。これで、PCSSの衣装も濡れます。実験機能なので、先に[高度な機能](./advanced.mdx#experimental)を読んでください。
- PCSS4VRCがシェーダーを差し替えないlilToonのユーザーシェーダーを使うパーツは、アップロードでも濡れます。
- 実験機能をオンにしても、PCSS4VRCがlilToonの**Multi**・**MultiOutline**（およびTessellation・Lite）系統を差し替えたパーツは濡れず、NDMFの警告が表示されます。1.0.0の警告は機能をオンにするよう案内することがありますが、すでにオンならこの系統が原因です。そのマテリアルをlilToonの標準シェーダーに変えるか、PCSS4VRCの変換対象から外してください。

## VRCFuryが古い {/* #vrcfury-old */}

VRCFuryを一緒に使うアバターで、ビルドのときに`SweatAmount`という言葉を含むエラーが出る場合は、VRCFuryが古い版の可能性があります。1.1258以下のVRCFuryで、このエラーが確認されています。

**解決:** VCCでVRCFuryを**1.1436.0以上**に更新してから、ビルドし直してください。VRCFuryを使わないアバターには当てはまりません。

## 衣装メッシュを変えるツール {/* #mesh-tools */}

アップロード中に衣装メッシュの頂点の順番、サブメッシュ、メッシュの構造を変えるツールは、<ProductName />と互換性がないことがあります。裂け防止（アンチリッピング）ツールやポリゴン削減ツールが、その例です。

- <ProductName />は、濡れのデータを衣装メッシュに合わせて入れます。ほかのツールがメッシュを変えて合わなくなった衣装やパーツは、濡れなしで乾いたままアップロードされます。
- ビルドは止まりません。NDMFのビルド結果ウィンドウに、その衣装（またはパーツ）の名前と理由が警告として残ります。
- AAO（Avatar Optimizer）、d4rk Avatar Optimizer、TexTransToolには対応しています。[互換性](./compatibility.mdx#optimizers)を確認してください。
- その衣装を濡らすには、そのツールの対象から濡れる衣装を外して、ビルドし直してください。

## 対応していない、または確認されていないシェーダー {/* #shaders */}

| 場合 | 結果と解決 |
| --- | --- |
| Sunao、UnityChanToon、UTSのような他の系統 | 濡れを入れずに、元の見た目でアップロードされます。 |
| Poiyomi Fur、Grab Pass、パッケージの外にコピーしたPoiyomi、名前だけが似ているカスタムシェーダー | 元の見た目のままにします。 |
| lilToon Fur、Gem、ユーザーが改造したlilToon | 元の見た目のままにします。 |
| lilToon Refraction / RefractionBlur | 濡れた色と光沢だけを加えます。追加の透けは入れません。 |
| まだ確認されていないPoiyomiのバージョン | そのシェーダーを使う衣装だけが乾いたままビルドされ、NDMFの警告が出ます。<ProductName />の更新をお待ちください。 |
| ロックされた（Locked）Poiyomiマテリアル | 元のシェーダーの情報が見つかれば濡れます。見つからない場合は、案内が出ます。 |
| Poiyomi 11の**Poi > Installed Modules**で、<ProductName />の内部モジュールをオンにした | オンにしないでください。オンにすると、Poiyomiの服が濡れません。 |

試験したシェーダーのバージョンは、[互換性](./compatibility.mdx#shaders)にあります。

## 1つのシーンにアバターが複数ある {/* #multiple-avatars */}

<ProductName />は、アバターごとに別々に動作します。同じシーンにアバターが複数あっても、互いの設定を使うことはありません。

- アバターごとに、別々にインストールする必要があります。インストール画面の**アバター**欄で、今選んでいるアバターが正しいか確認してください。
- 1つのアバターに`RealWet`オブジェクトが2つ以上あると、**重複エラー**が表示されます。1つだけ残してください。
- 他のアバターからコピーしてきた衣装が、そのアバターのボディやボーンを指している場合は、何がどのアバターを指しているかと、直し方をプレビューが知らせます。
- 2つ目のアバターで最初に確認したのが、髪のように、もともと濡れにくいパーツではないか確認してください。シャツのように体に触れる服で先に確認すると、違いがわかりやすくなります。
- NDMF・Modular Avatarは、正式版で確認しています。試験版（ベータ）を使っている場合は、正式版に替えてから、もう一度確認してください。

## 保存していない新しいシーン {/* #unsaved-scene */}

<strong>アバターに安定したシーン識別子がありません。シーンを保存してからもう一度お試しください。</strong>と表示された場合は、アバターが、まだ一度も保存していない新しいシーン（Untitled）にある、という意味です。

**解決:** **File > Save**でシーンを保存してから、もう一度インストールまたはプレビューしてください。

## 最初のビルドに時間がかかる {/* #long-first-build */}

初めてビルドするときや、初めてプレビューするときは、濡れシェーダーを作り、Unityがコンパイルします。マテリアルが多いアバターでは、**数十分**かかることがあります。このとき、Unityのウィンドウがほとんど動かず、止まったように見えることがあります。

{/* SHOT U28: build progress bar */}

1. **お待ちください。** アップロード中は、`RealWet: 衣装の形状を計算中 (3/22) · 衣装名`のように、段階と順番、衣装名が進行表示に出ます。Unity自体のシェーダーのコンパイル中は、進行表示が長い間そのままのことがあり、ウィンドウなしで進むこともあります。
2. **タスクマネージャーでCPUを確認します。** Unityや`UnityShaderCompiler`がCPUを使っていれば、まだ処理中です。終了せずに待ってください。
3. CPUが数分間ほぼ0%で、進行表示も変わらないときだけ、止まったと判断します。そのときは、Consoleの最初の赤いエラーと、待った時間を記録して問い合わせてください。

- 2回目のビルドからは、最初のビルドで作ったシェーダーのキャッシュを使い回すため、ずっと短くなります。
- 配信や録画のようにPCが忙しいときは、さらに時間がかかります。最初のビルドは、PCが空いているときに済ませておくのがおすすめです。
- **RealWet > 衣装管理 > 必要な衣装のみ準備**で、ビルドの前に準備しておけます。
- インストール画面の**インストール**・**更新**と、再生（Play）に初めて入るときにも、進行状況バーが表示されます。今している作業が表示されている間は、お待ちください。

詳しい時間は、[パフォーマンス](./performance.mdx#build-time)を確認してください。

## 最初のアップロードに時間がかかる {/* #first-upload */}

最初のアップロードでは、最初のビルドと同じシェーダーの準備に加えて、VRChat SDKのシェーダーのコンパイルと、アップロードファイルの圧縮があるため、時間がかかります。

- 濡れるマテリアルごとに濡れシェーダーが入るため、アップロードファイルが大きくなり、圧縮にも時間がかかります。[パフォーマンス](./performance.mdx#upload-size)を確認してください。
- アップロードのときに、Poiyomiがマテリアルをロックする時間も加わります。
- 同じ設定なら、2回目のアップロードからは短くなります。

## Hold onウィンドウ {/* #hold-on */}

Unityの**Hold on**ウィンドウは、Unityが処理を終えるまで待ってほしい、という意味です。

| いつ | 原因と解決 |
| --- | --- |
| 最初のプレビュー、最初のビルド、シェーダーを更新した直後 | 濡れシェーダーを準備しています。お待ちください。 |
| パッケージをインポートした直後 | Unityがスクリプトとシェーダーをインポートしています。お待ちください。 |
| Unityを前面に出したまま、何もしていないとき | <ProductName />は、Unityが背面にあるときだけ事前に準備します。それでも出る場合は、他のツールやUnity自体の処理かもしれません。 |
| 他のアプリを使ってから、Unityに戻ったとき | 事前の準備を止めるための、短い時間です。途中で止められないシェーダーの準備は、Unityが3分以上背面にあるときだけ始めます。 |

同じ操作で**Hold on**が何度も長く出る場合は、その操作とConsoleの内容を記録して問い合わせてください。

## メニュー・パラメーターが上限を超える {/* #over-limit */}

VRChatでは、1つのアバターで同期パラメーターを**256ビット**まで使えます。<ProductName />のおすすめメニューは87ビットです。RealSweatSystemや他のツールと合わせて上限を超えると、VRChat SDKがアップロードを止めます。

1. **RealWet > ゲーム内メニュー**の**最終同期コスト**で、<ProductName />が使う量を確認します。
2. 使わないダイヤルのチェックを外します。ダイヤルは1つにつき8ビット、トグルは1ビットです。たとえば、**濡れる範囲を広げる**、**濡れの境界**、**濡れ表現**を外すと、24ビット減ります。
3. **ゲーム内メニューを適用 / 更新**を押して、ビルドし直します。

- ボタンを外した機能は、Unityで決めた値のまま動き続けます。
- メニューの1ページは8枠です。<ProductName />は、枠が足りないと**次へ**のページを作り、メインメニューは増やしません。
- VRCFury Parameter Compressorのような、パラメーターを圧縮するツールを使うこともできます。圧縮ツールが濡れのパラメーターを変えた場合は、NDMFの結果ウィンドウでお知らせします。

## メニューが見当たらない {/* #menu-missing */}

1. メインメニューで**濡れ**（英語は**Wet**、韓国語は**젖음**）を探します。
2. メニューの場所を変えた場合は、`RealWet`オブジェクトの**MA Menu Installer**に指定したメニューの中を確認します。
3. **RealWet > ゲーム内メニュー**で、**ゲーム内メニューを適用 / 更新**を押します。
4. ビルドし直して、そのアバターを確認します。ビルドが失敗していた場合は、前のアバターを見ている可能性があります。

- メニューファイルがなくなった場合は、保存されたシーンを開いたときに、<ProductName />が作り直して接続します。コンソールに<strong>RealWet のゲーム内メニューファイルがなかったため、RealWet が作り直してつなぎました。シーンを保存してください。</strong>と残るので、シーンを保存してください。
- メニューを手動で移動したり、別のメニューに置き換えたりした場合、<ProductName />はそのメニューをそのままにします。作り直すには、`RealWet`オブジェクトの**MA Menu Installer**を削除してから、**ゲーム内メニュー**タブの**ゲーム内メニューを修復**を押してください。
- メニューが別の言語で表示される場合は、Unityで使いたい言語を選んでからメニューを更新し、ビルドし直してください。
- メニューのボタンはあるのに、アイコンだけがない場合は、パッケージの`Icons`フォルダーをインポートし直してから、メニューを更新してください。機能はそのまま使えます。

## 再生すると一部の衣装が濡れない {/* #play-not-ready */}

再生ボタンを押したときに、まだ準備ができていない衣装があると、<ProductName />は再生を少し待たせて、その衣装を準備します。準備が終わると、再生が自動で始まります。

{/* SHOT U29: Game view overlay before Play */}

- 待っている間に再生ボタンをもう一度押すと、すぐに始まります。このとき、準備ができていない衣装は、その再生でだけ濡れません。
- 再生を終えると、その衣装から準備し、次の再生から濡れます。
- 再生を始めたときにオフで、再生中にオンにしたアバターは、その再生では濡れません。アバターをオンにした状態で、もう一度再生してください。

## テクスチャの上限 {/* #texture-limit */}

PC向けのUnityとVRChatでは、シェーダーの1パスが使うテクスチャは64個までしか描画できません。機能を多くオンにしたPoiyomiマテリアルは、プレビューではロックする前のシェーダーを使うため、濡れを加えると、この上限を超えることがあります。

- そのようなスロットは、ピンクではなく元の見た目でプレビューし、案内を表示します。
- VRChatのPC向けアップロードでは先にシェーダーをロックするため、このスロットは、たいてい濡れた状態でアップロードされます。
- アップロードの最終的なシェーダーも上限を超える場合は、そのマテリアルだけが元の乾いたマテリアルに戻ります。アップロードは止まりません。
- 濡れを保つには、そのマテリアルで使っていないテクスチャ機能（MatCap、発光、デカールなど）を減らしてから、ビルドし直してください。

## 登録済みの衣装が0件 {/* #no-outfits */}

1. インストールしたアバターの下にある`RealWet`を選んでいるか確認します。
2. **衣装管理 > 自動で探す > 今すぐ検索**を押します。
3. 漏れた服は、**手動で追加**にHierarchyの衣装ルートを入れて、**追加**を押します。

- `EditorOnly`の衣装は、初期設定では探しません。
- 衣装ルートがボディ・顔のメッシュオブジェクトの中にあると、登録されないことがあります。[衣装設定](./usage/outfit-settings.mdx)を確認してください。
- <strong>×</strong>で削除した衣装は、自動ではもう一度追加しません。手動で追加してください。

## プレビューの問題

| 症状 | 解決 |
| --- | --- |
| まったく始まらない | **Tools > NDM Framework > Enable Previews**がオンか、Edit Modeかを確認します。 |
| 時間がかかる | Inspectorの現在の段階を確認します。最初は、シェーダーの準備のために時間がかかります。ボタンを押し直す必要はありません。 |
| **一時停止中 · Unityに戻ってください** | 他のアプリに切り替えただけです。Unityに戻ると続きます。 |
| 途中で終わる | 関係のないオブジェクトを選んだり、再生・ビルド・スクリプトの再読み込みが起きたりすると終わります。もう一度開始すれば大丈夫です。 |
| 準備が必要だと何度も表示される | 開始方式、範囲、衣装の形、シェーダーを変えると、準備し直します。何も変えていないのに繰り返す場合は、衣装名と理由を記録して問い合わせます。 |

## 以前のバージョンの上から更新する {/* #updating */}

1. 更新する前に、プロジェクトをバックアップしてください。
2. `Assets/CookiTools/RealWetSystem`フォルダーは削除せず、新しいパッケージを、その上にそのままインポートしてください。先にアンインストールする必要はありません。
3. インポートした直後にConsoleに赤いエラーが残っている場合は、Unityを一度再起動してください。
4. インストール画面で、アバターごとに**更新**を押します。
5. 最初にプレビューまたはビルドするときは、濡れシェーダーを準備し直すため、1回だけ時間がかかります。

- 保存された設定、開始点、保護範囲は、そのまま残ります。
- 手を加えていない以前の標準の見た目だけが、1回だけ新しい標準の見た目に変わります。このとき、**RealWet > 衣装管理**に、お知らせと<strong>元に戻す…</strong>が表示されます。
- 保存された開始点の配置が新しいおすすめの配置と違う場合は、更新のときに**濡れ開始点をリセット** / **既存の設定を維持**を尋ねます。よくわからない場合は、**既存の設定を維持**を選んでください。
- 新しいおすすめの保護の形を使うには、[更新した後の保護範囲](./usage/see-through-protection.mdx#after-update)を確認してください。

詳しい手順は、[更新履歴](./update-changelog.mdx#how-to-update)にあります。

## アンインストール {/* #uninstall */}

- **衣装を1つだけ外す:** **RealWet > 衣装管理**のその衣装の行で<strong>×</strong>を押すか、**濡れ機能を使用**をオフにします。服そのものは残ります。
- **アバターからすべて外す:** **CookiTools > RealWetSystem > Setup／Uninstall**の**アンインストール**タブで、**アンインストール**を押します。確認ウィンドウで**アンインストール**を押すと、`RealWet`オブジェクトとその下の内容、衣装の<ProductName />コンポーネント、このインストールのメニューファイルを片付けます。衣装・ボディ・元のマテリアルは残ります。確認ウィンドウにも書かれているとおり、削除はCtrl+Zで元に戻せません。
- `RealWet`オブジェクトの下には、他の衣装やツールを入れないでください。アンインストールのときに、一緒に削除されます。
- 最初のインストール、全体のアンインストール、ゲーム内メニューの作成・更新・削除は、Ctrl+Zで元に戻せません。
- プロジェクトからパッケージまで削除するには、すべてのアバターで先に**アンインストール**をしてから、`Assets/CookiTools/RealWetSystem`フォルダーを削除してください。

## 問い合わせる {/* #support */}
