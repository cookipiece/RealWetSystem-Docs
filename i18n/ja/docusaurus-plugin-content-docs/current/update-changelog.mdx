# 更新履歴

このページでは、<ProductName />のバージョンごとの主な変更を、新しい版から順にまとめています。新しい版に切り替える前に、下の更新の方法を先に確認してください。

## 更新の方法 {/* #how-to-update */}

1. 更新する前に、アバターとプロジェクトをバックアップしてください。
2. `Assets/CookiTools/RealWetSystem`フォルダーは削除しません。新しいパッケージを、その上にそのままインポートしてください。先にアンインストールする必要はありません。
3. インポートすると、<ProductName />が古い版にだけあったファイルをシステムのごみ箱に移し、コンソールに1行で知らせます。手動で入れたファイルと、新しいパッケージが使うファイルには触れません。
4. インポートした直後にConsoleに赤いエラーが残っている場合は、Unityを一度再起動してください。
5. 新しい版の修正は、インポートしてアップロードし直すだけで適用されます。新しいゲーム内メニュー項目を入れるには、**CookiTools > RealWetSystem > Setup／Uninstall**で、アバターごとに**更新**を一度押します。
   - 1.0.3では、RealSweatSystemと一緒に使うアバターに**濡れた衣装を自分にだけ表示**が入り、同期ビットを1ビット多く使います。
   - 保存された開始点の配置が新しいおすすめの配置と違う場合は、**RealWetSystemの更新**ウィンドウが**濡れ開始点をリセット** / **既存の設定を維持** / **キャンセル**のどれにするかを尋ねます。よくわからない場合は、**既存の設定を維持**を選んでください。更新している間は、進行状況バーが表示されます。

{/* SHOT U13: update dialog Reset Wet Start Points / Keep Current Settings */}
[![更新時の濡れ開始点リセットの確認](/img/guide/U13-ja.png)](/img/guide/U13-ja.png)

6. 更新した後、最初にプレビューまたはビルドするときは、濡れシェーダーを準備し直すため、1回だけ余分に時間がかかります。
7. アップロード済みのアバターは、アップロードし直すと新しい版が適用されます。
   - 新しいゲーム内メニュー項目を使うには、アップロードし直す前に**更新**を押します。**RealWet > ゲーム内メニュー**でその項目にチェックを入れて、**ゲーム内メニューを適用 / 更新**を押してもかまいません。

- 保存された設定、開始点、保護範囲はそのまま残ります。新しいおすすめの保護の形を使うには、[更新した後の保護範囲](./usage/see-through-protection.mdx#after-update)を確認してください。
- 手を加えていない以前の標準の見た目だけが、1回だけ新しい標準の見た目に変わります。このとき、**RealWet > 衣装管理**にお知らせと<strong>元に戻す…</strong>が表示されます。インストール画面の**更新時に新しい標準に変更する**をオフにして更新すると、変わりません。
- アバターごとに作るメニューファイルは、パッケージのフォルダーの外にある`Assets/CookiTools/Generated/RealWet`にあるため、パッケージを上書きしても消えません。
- 更新には購入認証は必要ありません。ただし、認証していないPCからアップロードすると効果が外れるため、アップロードするPCで[購入認証](./license-activation.mdx)をしておいてください。

## 1.0.4 — Avatar Optimizerと一緒に使うと衣装が濡れなかったケース {/* #104 */}

1.0.3またはそれより前の版をお使いの方は、新しいパッケージをそのまま上書きインポートして、アップロードし直してください。保存した設定と、濡れ開始点・保護範囲の位置は変わりません。ゲーム内メニュー、パラメーター、同期ビットもそのままです。1.0.4には新しいゲーム内メニュー項目がないため、インストール画面の**更新**を押す必要はありません。

- Avatar Optimizer（AAO）の**Trace and Optimize**は、同じマテリアルを使うマテリアルスロットを1つに結合します。それらのスロットの濡れ設定（透けなど）が異なると、1.0.3までは、プレビューでは濡れていた衣装がまるごと乾いたままアップロードされていました。1つのメッシュの中で同じマテリアルを2つ以上のスロットに使う衣装を<strong>上着だけ透ける（下着は透けない）（推奨）</strong>で登録すると、スロットごとに濡れ設定が異なることがあります。1.0.4からは、それぞれのスロットがプレビューと同じ設定で濡れます。<ProductName />が変更するのは、アップロード用のコピーだけです。元のマテリアルと保存した設定は変わりません。
- ほかのツールがそれらのスロットを1つのマテリアルに結合し直すと（マテリアルを結合するテクスチャアトラスなど）、結合されたスロットは1つの濡れ設定で濡れます。<ProductName />は、どのパーツも設定より強く透けない設定を選び、NDMFのビルド結果に**RealWet: 結合されたマテリアルスロットは濡れ設定を1つだけ使います**と表示して知らせます。同じ衣装のほかのパーツは、いつもどおり濡れます。
- 濡れないようにオフにしたスロットが、濡れるスロットと同じマテリアルを使っている場合、オフにしたスロットはプレビューと同じく乾いたままになります。1.0.3までは、AAOが2つのスロットを結合するため、オフにしたスロットも一緒に濡れていました。
- AAO 1.9.0以上であれば、<ProductName />がAAOの自動メッシュ結合に対応し、濡れを適用します。1.0.3までは、AAO 1.9.15以上でしか対応していなかったため、それより前のAAOでは、自動で結合されたパーツが乾いたままアップロードされていました。AAOが1.9.0より前の場合は、これまでどおりそのパーツだけが乾き、NDMFのビルド結果に出る乾いたパーツの案内に、原因と必要なAAOのバージョンが表示されます。[互換性](./compatibility.mdx#optimizers)
- 上のケースに当てはまらない衣装は、これまでと同じようにビルドされます。

## 1.0.3 — 濡れなかったケース、胸のボーンの指定、濡れた衣装を自分にだけ表示 {/* #103 */}

1.0.2またはそれより前の版をお使いの方は、新しいパッケージをそのまま上書きインポートしてください。保存した設定と、濡れ開始点・保護範囲の位置は変わりません。インストール済みのアバターのゲーム内メニュー、パラメーター、同期ビットも、**更新**を押すまではそのままです。

:::note[更新した後の最初のアップロードは、1回だけ時間がかかります]
更新した後の最初のアップロードでは、濡れシェーダーを一度コンパイルし直します。衣装の多いアバターでは、20分ほどかかることがあります。進行表示が変わらなくても、UnityがCPUを使っていれば、終了せずにお待ちください。最初のプレビューもいつもより少し時間がかかることがあり、2回目からはいつもどおりです。
:::

### インストール画面で胸のボーンを指定

- インストール画面の**1. 身体の登録**で、ボディメッシュの下に**左胸の基準ボーン**・**右胸の基準ボーン**の欄が常に表示されます。自動で見つけたボーンが欄に入っていて、違う場合はアバターの胸のボーンをドラッグして入れます。**胸のボーンを自動検出**は、手動で入れたボーンを消して探し直します。3番のカードの下にあった胸のボーンの**変更**の行はなくなりました。[身体の登録](./tutorial.mdx#body)
- ボディメッシュにウェイトのないボーン（衣装のボーンなど）を入れると、欄の下に知らせます。
- インストール済みのアバターで胸のボーンを変えると、**胸の開始点・保護領域を新しいボーンに合わせて置き直す**のチェック欄が表示されます（初期値はオフ）。チェックして**更新**を押すと、胸まわりの濡れ開始点と推奨の胸の保護範囲の位置だけを、新しいボーンに合わせます。大きさ、ほかの開始点、自分で作った範囲はそのままです。チェックしない場合は、ボーンの選択だけを保存し、保存された位置は動きません。

### ボーンスケールで小さくしたり、比率を変えたりしたアバター

- ボーンスケール（Hips・Armatureなど）で小さくしたアバターで、胸の開始点と推奨の胸の保護範囲が、小さくする前と違う場所に置かれていた問題を直しました。これからは、同じ体なら小さくしても同じ場所に置きます。
- ボーンスケールで小さくしたアバターでは、濡れ開始点の大きさと探す範囲を、小さくした体に合わせます。
- ボーンスケールで胴体だけを短くしたアバターで胸の保護範囲が体の内側に置かれていた問題と、二の腕をボーンスケールで小さくしたアバターで脇の開始点が肩の上に置かれていた問題を直しました。
- 胸のボーンの欄に末端のボーンを入れても、推奨の胸の保護範囲は、その胸のボーンのつながり全体から胸の前を探します。
- この修正は、新しく作る開始点と保護範囲（新規インストール、リセット、上のチェック欄）にだけ使われます。保存された位置は変わりません。ボーンスケールで小さくしていないアバターの配置も変わりません。

### 濡れなかったケースと、表示が崩れていたケース

- **アニメーションで切り替えるマテリアルにもWetを適用**をオフにして、マテリアルを切り替えるアニメーションを使うPoiyomi Toon・Proのパーツが、正しく濡れなかった問題を直しました。Poiyomi 10.0.20以降とPoiyomi 11では、UV0が重なるパーツ（左右対称など）が乾いたままアップロードされ、それより前のPoiyomiでは、アウトラインを使わないマテリアルのパーツがアップロード時の確認を通らず、警告が出ていました。
- UV3とUV4の両方を使うPoiyomi 10.0.20以降・Poiyomi 11のパーツで、濡れマテリアルがテクスチャ数の上限（64個）を超えると、そのスロットが見えなくなったり、ピンクに見えたりすることがあった問題を直しました。これからは、ほかのパーツと同じように、そのスロットだけが元のマテリアルに戻ります。[テクスチャの上限](./troubleshooting.mdx#texture-limit)
- プロジェクトに`LILTOON_DISABLE_ASSET_MODIFICATION`が設定されていて、lilToonの衣装がすべて乾いたままビルドされるとき、この設定が原因であることと、どこに設定されているか、直す方法を案内します。1.0.2までは、**まだ確認されていない lilToon のバージョン**と案内していました。案内には、**設定から削除して lilToon の衣装を濡らす**ボタンがあります。[lilToonのシェーダーインポーターがオフになっている](./troubleshooting.mdx#liltoon-importer-off)
- プロジェクトの別のアセットがlilToonのインポータースクリプトのGUIDを持っているプロジェクトで、lilToonの衣装がすべて乾いたままビルドされていた問題を直しました。このようなプロジェクトでは、<ProductName />のlilToonシェーダーファイル（`.lilcontainer`）を選ぶと、Inspectorの上部に`(Failed To Load Script Object)`と表示されます。<ProductName />は、プロジェクトのファイルを変更しません。[lilToonの衣装が乾き、(Failed To Load Script Object)と表示される](./troubleshooting.mdx#liltoon-script-object)
- **診断レポートをコピー**のレポートに、lilToonのインポーターをどこで見つけたかと、<ProductName />のlilToonシェーダーファイルがシェーダーとしてインポートされているかが入ります。

### 濡れた見た目

- ゲーム内の<strong>濡れ光沢（50%=標準）</strong>を50%より上げても、白い服・明るい服ではほとんど変わって見えなかった点を直しました。<strong>衣装ごとに均一に濡れて見えるようにする（新しい見た目）</strong>をオンにした衣装（初期設定）で、<strong>綿・ニット・デニム（おすすめ）</strong>と**中間**の生地の明るい服は、50%を超えると広い水の光沢が大きく増え、100%では白い服でも濡れた光沢がはっきり見えます。光沢は、これまでどおり、そのシーンの白より明るくなりません。
- 50%以下、中くらいの明るさの服と暗い服、ほかの生地、新しい見た目をオフにした衣装は、これまでと同じです。保存した設定は変わりません。濡れ光沢を50%より高くして使っていたアバターは、更新した後にアップロードし直すと、明るい服が前よりも光ります。

### ゲーム内メニュー

- RealSweatSystemと一緒に使うアバターの**濡れ**メニューに、**濡れた衣装を自分にだけ表示**（韓国語は**젖은 옷 나에게만 보이기**、英語は**Wet Clothes Only Visible to Me**）を追加しました。オンにしている間、ほかの人には衣装が乾いた見た目（濡れた色・光沢・透けなし）で見え、自分には鏡や写真でもそのまま見えます。保存・同期されるトグル1つ（+1ビット）で、オフの状態で始まります。[濡れた衣装を自分にだけ表示](./usage/in-game-menu.mdx#linked-local-only)
- **透け防止**ページのいちばん下に入り、そのページがないアバターでは、メインページの<strong>現在の状態を固定（撮影用）</strong>の次に入ります。ほかのメニュー項目の場所は変わりません。どちらにも空きがない場合は、そのアップロードには入れず、NDMFのビルド結果で知らせます。ビルドは続きます。
- インストール済みのアバターには、インストール画面で**更新**を押したときに入ります（オフの状態で始まります）。それまでは、メニュー、パラメーター、同期ビットはそのままです。保存されたほかの設定とゲーム内の値も変わりません。
- RealSweatSystemなしで使うアバターの**自分にだけ表示**は、これまでと同じです。2つのトグルは、同じパラメーター（`Cooki/ClothWetLocalOnly`）を使います。
- RealRainの雨で濡れた見た目も、ほかの人には見えません。
- このトグルが入るアバター（RealSweatSystemと一緒に使うアバター）のおすすめメニューは88ビット、すべての項目を入れると95ビットです。RealSweatSystemなしで使うアバターは、87ビットと94ビットのままです。[同期容量](./usage/in-game-menu.mdx#sync-cost)

### 案内と文言

- VRCFuryを使う場合は、1.1436.0以上を使ってください。同期パラメーターの容量（256ビット）が足りない場合は、VRCFury 1.1436.0以上のParameter Compressorを一緒に使うことをおすすめします。[互換性](./compatibility.mdx#requirements)
- 試験したPoiyomiのバージョンに、11.0.44を追加しました。[互換性](./compatibility.mdx#shaders)

## 1.0.2 — 濡れなかったケースと、インストール中に止まったように見えた区間 {/* #102 */}

1.0.1または1.0.0をお使いの方は、新しいパッケージをそのまま上書きインポートしてください。保存した設定は変わりません。ゲーム内メニューのパラメーターと同期ビットもそのままで、英語・日本語・韓国語のメニュー名のいくつかだけが、次のアップロードから変わります。

### 濡れなかったケース

- VRCFury 1.1258以下を使うアバターで、アップロードした服がすべて濡れなかった問題を直しました。VRCFuryは、これからも1.1436.0以上を使ってください。[VRCFuryが古い](./troubleshooting.mdx#vrcfury-old)
- RealSweatSystemと連動したアバターをアップロードするときに、RSSの汗の入力を使えない場合（このPCでRealSweatSystemの購入認証をしていない場合、汗のパラメーターの同期をオフにした場合など）、服がすべて乾いていた動作を変えました。これからは、**RealSweat連動**をオフにしたときと同じように、ゲーム内の<strong>濡れ量（連動OFF時）</strong>ダイヤルでビルドし、NDMFのビルド結果に原因とやることを表示します。
- インストールした後で、パーツ欄のマテリアルを同じ系統の別のマテリアル（同じ衣装の色違いなど）に替えると、その欄の濡れた見た目・透けの設定が初期化されていた問題を直しました。これからは設定を引き継ぎます。
- シャツとビキニのように、1つの衣装の中で重なったパーツが、<strong>上着だけ透ける（下着は透けない）（推奨）</strong>で1つも透けなかった問題を直しました。これからは、外側のパーツが透け、その下の内側のパーツは透けません。新しく登録する衣装にだけ適用されます。
- 実験機能のlilSSRT・PCSS4VRC(lilToon)を使う一部の衣装が、ビルドで乾いていた問題と、lilSSRTの半透明の衣装の描画順が変わっていた問題を直しました。既存のlilSSRTの衣装は、更新した後に一度準備し直します。[高度な機能](./advanced.mdx#experimental)
- 衣装のFBXのRead/Writeがオフで、VRCFuryがビルド中にその衣装のマテリアルのコピーを作ると、衣装がすべて濡れなかった問題を直しました。Avatar Compressor（LAC）を一緒に使っても濡れます。FBXの設定は変更しません。[ほかのツールがビルド中にマテリアルを変えて濡れない](./troubleshooting.mdx#material-replaced)

### インストール・衣装の追加中に止まったように見えた区間

- 衣装を選ぶウィンドウの**おすすめどおり追加**・**選んだ衣装を追加**で、衣装ごとに進行状況バーに名前が表示されます。何着追加しても、体は1回だけ読み込みます。結果は同じです。
- **インストール**の胸・股の透け保護の段階でも、進行状況バーが動き続けます。
- **インストール**を押したときに、シーンに保存していない変更があれば、**保存してインストール** / **保存せずにインストール**を一度だけ確認します。
- Unityが後ろに回っているときに行うシェーダーの事前準備で、<strong>RealWet シェーダー準備中（n/m）</strong>の進行状況バーが表示されます。シェーダーが1つ終わるたびにユーザーが戻ってきたかを確認し、戻ってきていればそこで止めて、次に続きを行います。空きメモリが4 GBより少ないときは後回しにします。
- プレビューが、再生（Play）と同じように濡れシェーダーを2つずつ準備します。シェーダーのコンパイルに使うメモリが減り、結果は同じです。
- インストール画面とプレビューが、画面を描き直すたびに行っていた不要な処理をなくしました。

### 案内と文言

- PCSS4VRCを使うアバターのlilToon Multi・Tessellation・Liteのパーツは、実験機能をオンにしてもアップロードでは濡れないことを、プレビューの上の案内・パーツ欄・インストール画面の**実験機能**欄・NDMFのビルド結果で知らせます。[PCSS4VRCがマテリアルを差し替える](./troubleshooting.mdx#pcss)
- lilSSRT・PCSS4VRCをオンにするかを尋ねる最初のインストール時の確認は、このアバターがそのシェーダーを実際に使うときだけ表示されます。
- Poiyomi 8.x以下・PCSS4Poiのパーツには、濡らす方法（Poiyomi 9以上）も案内します。
- 古いlilSSRTの上に新しいlilSSRTをインポートして、シェーダーが古いフォルダー（例: `Shaders/SSRTAO`）に残った場合は、見つかったフォルダーと直す手順を案内します。[lilSSRTのシェーダーが古いフォルダーに残っている](./troubleshooting.mdx#lilssrt-old-folder)
- PoiyomiにRealWetの内部モジュールをインストールしたときの案内が、**Poi > Installed Modules**メニューのない最近のPoiyomiでも合うようになりました。ほかの作者のシェーダーモジュールを入れたPoiyomiにも、そのモジュールを外す方法を案内します。[PoiyomiでRealWetの内部モジュールをインストールした](./troubleshooting.mdx#poi-internal-module)
- ほかのツールがビルド中に作ったマテリアルのコピーのせいでパーツが濡れなかったとき、NDMFのビルド結果に、どの確認が合わなかったかも書きます。[ほかのツールがビルド中にマテリアルを変えて濡れない](./troubleshooting.mdx#material-replaced)
- **診断レポートをコピー**のレポートに、インストールされている実験機能のシェーダー（lilSSRT・PCSS4VRC(lilToon)）ごとに、オンにしたか、使えるか、見つかった場所、確認したバージョンが入ります。
- アップロードのたびにConsoleに出ていた黄色い警告1行を、通常のログに変えました。

- 日本語の復旧案内の抜けていた部分を補いました。衣装を選ぶウィンドウの短い理由と、標準の濡れ開始点の名前は、いま選んでいる画面の言語で表示されます。保存値とHierarchyの目印の名前は変わりません。

### 含まれるもの

- **インストール画面:** **CookiTools > RealWetSystem > Setup／Uninstall**で、身体の登録、最大の濡れ範囲、濡れ始める方式、新しい衣装の濡れた見た目を選んで、4つの欄のすぐ下の**インストール**を押します。**連携とゲーム内メニュー**と**詳細設定**は、ボタンの下に折りたたまれています。ゲーム内メニューのリストは、ゲーム内のメニューと同じ名前・順番でページごとにまとまっていて、項目ごとに増える同期ビットが表示されます。インストール・更新している間は、進行状況バーが表示されます。オプションの意味は、[初心者チュートリアル](./tutorial.mdx#setup-options)にあります。
- **購入認証:** 新しくインストールするときに、PCごとに一度、購入認証が必要です。メニューは**CookiTools > RealWetSystem > Purchase Activation**です。認証していないPCからアップロードすると効果が外れますが、ビルドは止まらず、プレビューと再生ではそのまま表示されます。[購入認証](./license-activation.mdx)
- **衣装を選ぶウィンドウ:** インストールの案内を閉じると、濡らす衣装を選ぶウィンドウが開きます。<strong>おすすめどおり追加（N着）</strong>を1回押すと確実な衣装をすべて追加でき、**自分で選ぶ**で1つずつ選ぶこともできます。このウィンドウはUnityの操作を止めません。
- **濡れ方:** 服は、汗をかく所や体に触れる所から濡れます。濡れた部分は色が深くなり、しわに沿って水の光沢が出て、薄い服は透けます。生地（綿・ニット・デニム、ポリエステル・サテン・水着、ラテックス・ビニール・エナメル、中間）と強さ（控えめ、標準、強め）を選びます。<strong>衣装ごとに均一に濡れて見えるようにする（新しい見た目）</strong>が、初期設定でオンになっています。
- **lilToonとPoiyomi:** lilToon 2.3.0以上と、Poiyomi Toon / Pro（ロックされたマテリアルを含みます）が、同じ見た目で濡れます。
- **透け保護:** 新規インストールでは、胸・股のおすすめの保護範囲4つが、体に合わせて入ります。保護範囲も濡れ、濡れて生じる透けだけを防ぎます。乳首のシェイプキー、胸のボーン、胴体の順に位置を探すため、胸が平らなアバターにも置けます。[透け保護](./usage/see-through-protection.mdx)
- **ゲーム内メニュー:** アバターのメインメニューに、**濡れ**（韓国語は젖음、英語はWet）メニューが入ります。メインページは**衣装の濡れを表示**、**濡れ量**、**全範囲濡れ**、**高速乾燥**、<strong>現在の状態を固定（撮影用）</strong>の順で、その次に**透け防止**ページ（**大事な部分の透け防止**スイッチと、**透け防止の範囲**・**透け防止の強さ**のダイヤル）と、**濡れ調整**ページ（<strong>最大の濡れ範囲 (%)</strong>が最初の枠）があります。名前と順番は、RealSweatSystemの**汗**メニューに合わせました。おすすめ構成は、同期パラメーター87ビットです。[ゲーム内メニュー](./usage/in-game-menu.mdx)
- **濡れ開始点と保護範囲のエディター:** <strong>濡れ・保護範囲を編集…</strong>で、球を動かし、サイズと広がりを変え、左右ペアを作ります。選んだ球の影響が、体と服に色で表示されます。[濡れ開始点](./usage/wet-start-points.mdx)
- **RealSweatSystemとの連動:** 一緒に使うと、肌の汗の量に合わせて服も濡れます。RealSweatSystemの汗の表示は肌の汗にだけ適用され、衣装の濡れは**衣装の濡れを表示**で隠します。
- **RealRainSystemとの連動:** 一緒に使うと、雨に当たった服も濡れ、雨粒・水の筋が同じ服の上に描かれます。
- **ビルドは止まりません:** 濡れを入れられなかった部分だけが元の乾いたマテリアルでアップロードされ、NDMFの結果ウィンドウに衣装名と理由が警告として残ります。アップロード中は、<ProductName />の段階が進行表示に出ます。
- **最適化ツール:** AAO、d4rk Avatar Optimizer、TexTransToolと一緒にビルドしても、濡れが残ります。VRCFuryは、1.1436.0以上で一緒に使えます。濡れが消えるおそれのある設定は、インストール画面の**他のアバターツール**欄で事前に知らせます。[互換性](./compatibility.mdx#optimizers)
- **実験機能:** PCSS4VRC(lilToon)とlilSSRTを使う衣装も濡らせます。インストール画面の**詳細設定 > 実験機能**で、アバターごとにオンにします（初期値はオフ）。[高度な機能](./advanced.mdx#experimental)
- **編集中に止まりにくく:** 事前の準備は、Unityが後ろに回っているときだけ行います。登録した衣装を編集するときにUnityが数秒ずつ止まらないよう、計算を分けて行います。
- **言語:** 画面とゲーム内メニューの名前は、English / 한국어 / 日本語 から選べます。

### 既知の制限

- PC専用です。Quest・モバイルには対応していません。
- 購入認証は、Windowsでしかできません。Mac・LinuxのUnityからアップロードすると、<ProductName />の効果が外れます。
- 新規インストールは、Humanoidのアバターにだけできます。
- 異なる衣装どうしの重ね着の描画順は決めません。[重ね着の順序](./usage/outfit-settings.mdx#layer-order)を確認してください。
- SeeThroughHairがビルド中にシェーダーを変える半透明の髪のコピーは、濡れません。残りの髪は濡れます。
- アニメーションでレンダラーのメッシュそのものを切り替える構成には、対応していません。
- アップロード中に衣装メッシュの頂点の順番、サブメッシュ、メッシュの構造を変えるツール（裂け防止ツール、ポリゴン削減ツールなど）は、互換性がないことがあります。合わなくなった衣装やパーツは乾いたままアップロードされ、NDMFのビルド結果ウィンドウに理由が残ります。[衣装メッシュを変えるツール](./troubleshooting.mdx#mesh-tools)
- VRCFuryを使う場合は、1.1436.0以上を使ってください。1.1258以下で服が濡れなかった問題は、1.0.2で直しました。
- Poiyomi 8.x以下には対応していません。

そのほかの制限は、[技術仕様](./technical-specifications.mdx#known-limits)にあります。
